# 0.207 XDM-WOS100 레이어 구성도: 출력 1개에 4K/60 소스 4개 · HOS100 컨셉과 Analog Way 데이터시트 믹싱

## 요청

- 사용자 요청(2026-10-12, 휴대폰 화면 캡처와 함께): "wos 출력1개에 4K60 소스.4개를 VP처럼 레이어링 할 수 있게 변경해그리고 선도 꼬여 있어"
- 캡처 화면: 제품정보 XDM → WOS100 카드 상세 → "레이어 구성도 · 비교표 보기" 팝업의 구성도(0.203에서 그린 2×2 비디오 월 그림)
- 이어진 요청(같은 날, 첫 그림을 본 뒤): "HOS100카드와 컨셉과 아날로그웨이 브로셔와 잘 믹싱해봐"
  - HOS100 카드 컨셉: 0.205·0.206 HOS100 멀티뷰 팝업의 안내 상자와 배치 예시 카드(QMS 06과 같은 모니터 그림)
  - 아날로그웨이 브로셔: 0.203 요청 때 예시로 받은 Analog Way Aquilon RS4 데이터시트의 응용 구성도

## 문제

1. 0.203 구성도는 "WOS100 카드 1장 = HDMI 4포트로 2×2 비디오 월, 월 위에 레이어 4개"였습니다. 사용자가 확인한 동작은 "출력 1개에 4K/60 소스 4개를 비디오 프로세서처럼 레이어로 겹친다"입니다.
2. WOS100 → OUT 1~4로 가는 선 4개가 서로 교차했습니다. 예를 들어 OUT 2 선의 세로 구간(x 412)이 OUT 3 선의 가로 구간(y 366)을 가로질렀습니다. "HDMI 1~4" 글자도 선 위에 겹쳤습니다.
3. 화살촉이 선 색이 아니라 검은색으로 나왔습니다. SVG 마커 안의 `currentColor`가 선이 아니라 마커 쪽 색을 따랐기 때문입니다.
4. 휴대폰에서는 그림 최소 폭(640px) 때문에 가로 스크롤이 생겨, 정작 중요한 오른쪽 디스플레이가 화면 밖에 있었습니다.

## 변경

### 구성도 (`src/app.js` `layerCompareSvg`·`layerCompareTallSvg`)

- **흐름:** 소스 4개(PC 1·PC 2·카메라·미디어 서버, 각 4K/60) → 입력 카드(입력 1~4) → 매트릭스 → WOS100 레이어 1~4 → 합성 → OUT 1(HDMI 2.0) → 디스플레이 1대
- **디스플레이 화면:** 레이어 1은 배경(전체 화면, PC 1)입니다. 레이어 2·3은 서로 겹친 창이고, 레이어 4는 오른쪽 위 작은 창입니다. 창에는 흰 테두리와 그림자를 넣어 겹친 모습이 보이게 했습니다.
- **겹침 순서:** 디스플레이 아래에 "레이어 4 → 3 → 2 → 1(배경)" 순서를 칩으로 보여 줍니다.
- **색:** QMS 06 화면 구성 모드(`src/products.js` `LAYOUT_COLORS`)의 입력 1~4번 색(파랑·주황·초록·보라)을 씁니다. 소스·입력 포트·레이어·화면 창의 색이 같아서 어떤 소스가 어떤 레이어인지 바로 이어집니다.
- **선:** 신호선(`rt-layer-route`) 14개는 모두 한 방향 직선입니다. 가로 그림은 수평선, 세로 그림은 수직선이라 서로 교차하지 않습니다.
- **화살촉:** 색마다 마커를 따로 만들고 `markerUnits="userSpaceOnUse"`로 크기를 고정해, 굵은 출력선에서도 커지지 않습니다.
- **휴대폰:** 화면 폭 640px 이하에서는 같은 흐름을 위 → 아래로 그린 세로 그림(`rt-layer-svg-tall`, viewBox 420×862)을 보여 줍니다. PC 가로 그림(`rt-layer-svg-wide`, 980×486)은 숨겨 가로 스크롤이 생기지 않습니다. 두 그림이 한 문서에 함께 있으므로 그라데이션·그림자·화살촉 id 접두어를 다르게 둡니다(`rt-lw-`·`rt-lt-`). 숨긴 그림의 정의를 참조하면 색이 그려지지 않기 때문입니다.
- **나머지 모드:** 비디오 월 모드(4포트로 2×2 월 한 면)와 스위칭 모드(4포트 각각 출력, 심리스)는 처음에 그림 아래 "참고" 칸에 글로 넣었습니다. 믹싱 단계에서 팝업 안내 목록으로 옮겼습니다(카탈로그 9쪽, 카드 note와 같은 내용).
- **빼낸 내용:** 예전 그림의 "출력 슬롯 Multiview 기본 레이아웃(매뉴얼 KV08 32~34쪽)" 칸은 HOS100 멀티뷰 팝업(0.205)이 따로 다루므로 뺐습니다. 출처 줄의 매뉴얼 KV08 32~34쪽 표기도 함께 지웠습니다.

### HOS100 컨셉 + Analog Way 데이터시트 믹싱 (`openLayerCompare`, `wosLayouts`)

팝업 본문 순서는 다음과 같습니다: 소개 → 핵심 수치 띠 → 구성도 → 포트 조건 안내 상자 → 레이어 배치 예시 6종 → 안내 목록 → 비디오 프로세서 비교표.

| 요소 | 가져온 컨셉 | 내용 |
|---|---|---|
| 핵심 수치 띠(`.rt-wos-keys`) | Analog Way 데이터시트의 큰 숫자 강조 | 4 레이어(출력 1개) · 4K/60 레이어 소스 · HDMI 2.0 출력 4포트 · 커맨드 겹침 설정. 짙은 남색 칸에 하늘색 윗줄, 휴대폰은 2×2 |
| 구성도 레이어 칩 | Analog Way 응용 구성도의 흰 테두리 레이어와 "Layer n · 4K60p" | "레이어 n" 아래에 "4K/60"을 두 줄로 적고 흰 테두리를 둠 |
| 디스플레이 창 | HOS100·QMS 06 모니터 그림 | 창마다 같은 산 무늬(흰색 16%)를 얹음 |
| 포트 조건 안내 상자(`.rt-wos-warn`) | HOS100 팝업의 주황 안내 상자 | "레이어를 쓸 때 포트 사용 조건은 확인 중입니다", 그림·예시는 OUT 1 기준 |
| 레이어 배치 예시(`.rt-wos-grid`) | HOS100 팝업의 레이아웃 카드(`.rt-hos-grid` 재사용, `RtMonitorLayoutSvg`) | 6종(자유 배치, 배경 + PIP 3, PBP + PIP, 쿼드, L자형, 배경 + 하단 띠). 카드마다 레이어 수 배지와 설명이 있음. 겹치는 배치에는 HOS100의 포트 칩 대신 겹침 순서 칩(앞 → 뒤)을, 나란한 배치에는 "겹치지 않음"을 표시 |
| 안내 목록 | HOS100 팝업의 안내 목록 | 겹침 설정은 커맨드 전용, 비디오 월·스위칭 모드(카탈로그 9쪽). 구성도 안의 "참고" 칸을 이리로 옮겨 그림 높이를 줄임(가로 486 → 414, 세로 862 → 798) |

- **배치 예시의 성격:** 레이어 4개 이하를 출력 1개에 겹치는 대표 모양입니다. 제조사가 정한 프리셋 목록이 아니며, 배치는 커맨드로 설정합니다.
- **색과 숫자:** 칸 숫자는 레이어(소스) 번호이고, 색은 구성도와 같은 입력 1~4번 색입니다.
- **배경 숫자 위치:** 자유 배치에서는 배경 숫자가 창에 가려지지 않도록 비어 있는 왼쪽 아래로 옮겼습니다(칸의 숫자 위치 값 `lx`·`ly`).
- **카드 배치:** PC는 3개씩 2줄(`.rt-hos-grid.rt-wos-grid`), 휴대폰은 2개씩입니다.
- **제목 줄바꿈:** 휴대폰 폭에서는 제목이 한 줄로 남고 레이어 수 배지가 아래로 내려갑니다.
- **브랜드 요소:** Analog Way 로고·제품 이름·문구는 쓰지 않았습니다. 정리 방식만 참고했습니다.
