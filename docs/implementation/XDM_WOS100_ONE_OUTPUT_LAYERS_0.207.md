# 0.207 XDM-WOS100 레이어 구성도: 출력 1개에 4K/60 소스 4개

## 요청

- 사용자 요청(2026-10-12, 휴대폰 화면 캡처와 함께): "wos 출력1개에 4K60 소스.4개를 VP처럼 레이어링 할 수 있게 변경해그리고 선도 꼬여 있어"
- 캡처 화면: 제품정보 XDM → WOS100 카드 상세 → "레이어 구성도 · 비교표 보기" 팝업의 구성도(0.203에서 그린 2×2 비디오 월 그림)

## 문제

1. 0.203 구성도는 "WOS100 카드 1장 = HDMI 4포트로 2×2 비디오 월, 월 위에 레이어 4개"였습니다. 사용자가 확인한 동작은 "출력 1개에 4K/60 소스 4개를 비디오 프로세서처럼 레이어로 겹친다"입니다.
2. WOS100 → OUT 1~4로 가는 선 4개가 서로 교차했습니다. 예를 들어 OUT 2 선의 세로 구간(x 412)이 OUT 3 선의 가로 구간(y 366)을 가로질렀습니다. "HDMI 1~4" 글자도 선 위에 겹쳤습니다.
3. 화살촉이 선 색이 아니라 검은색으로 나왔습니다. SVG 마커 안의 `currentColor`가 선이 아니라 마커 쪽 색을 따랐기 때문입니다.
4. 휴대폰에서는 그림 최소 폭(640px) 때문에 가로 스크롤이 생겨, 정작 중요한 오른쪽 디스플레이가 화면 밖에 있었습니다.

## 변경

### 구성도 (`src/app.js` `layerCompareSvg`·`layerCompareTallSvg`)

- **흐름:** 소스 4개(PC 1·PC 2·카메라·미디어 서버, 각 4K/60) → 입력 카드(입력 1~4) → 매트릭스 → WOS100 레이어 1~4 → 합성 → OUT 1(HDMI 2.0) → 디스플레이 1대
- **디스플레이 화면:** 레이어 1은 배경(전체 화면, PC 1)입니다. 레이어 2·3은 서로 겹친 창이고, 레이어 4는 오른쪽 위 작은 창입니다. 창에는 흰 테두리와 그림자를 넣어 겹친 모습이 보이게 했습니다.
- **겹침 순서:** 디스플레이 아래에 "레이어 4 → 3 → 2 → 1(배경)" 순서를 칩으로 보여 줍니다.
- **색:** QMS 06 화면 구성 모드(`src/products.js` `LAYOUT_COLORS`)의 입력 1~4번 색(파랑·주황·초록·보라)을 씁니다. 소스·입력 포트·레이어·화면 창의 색이 같아서 어떤 소스가 어떤 레이어인지 바로 이어집니다.
- **선:** 신호선(`rt-layer-route`) 14개는 모두 한 방향 직선입니다. 가로 그림은 수평선, 세로 그림은 수직선이라 서로 교차하지 않습니다.
- **화살촉:** 색마다 마커를 따로 만들고 `markerUnits="userSpaceOnUse"`로 크기를 고정해, 굵은 출력선에서도 커지지 않습니다.
- **휴대폰:** 화면 폭 640px 이하에서는 같은 흐름을 위 → 아래로 그린 세로 그림(`rt-layer-svg-tall`, viewBox 420×862)을 보여 줍니다. PC 가로 그림(`rt-layer-svg-wide`, 980×486)은 숨겨 가로 스크롤이 생기지 않습니다. 두 그림이 한 문서에 함께 있으므로 그라데이션·그림자·화살촉 id 접두어를 다르게 둡니다(`rt-lw-`·`rt-lt-`). 숨긴 그림의 정의를 참조하면 색이 그려지지 않기 때문입니다.
- **나머지 모드:** 비디오 월 모드(4포트로 2×2 월 한 면)와 스위칭 모드(4포트 각각 출력, 심리스)는 그림 아래 "참고" 칸에 글로 남겼습니다(카탈로그 9쪽, 카드 note와 같은 내용).
- **빼낸 내용:** 예전 그림의 "출력 슬롯 Multiview 기본 레이아웃(매뉴얼 KV08 32~34쪽)" 칸은 HOS100 멀티뷰 팝업(0.205)이 따로 다루므로 뺐습니다. 출처 줄의 매뉴얼 KV08 32~34쪽 표기도 함께 지웠습니다.
