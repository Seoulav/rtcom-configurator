# 0.258.0 출력 카드 선택 버튼 색 구분 (2026-10-20)

## 1. 요청과 원인

- 사용자 요청 2026-10-20: 제품정보 XDM의 "07 화면 연출 시뮬레이터" 화면 캡처를 보내며 "XDM-WOS100과 XDM-HOS100 선택 버튼의 색상을 서로 다르게해서 눈에 띄게 해줘."
- 두 카드 선택 버튼(`data-ls-card="WOS100"`, `"HOS100"`)과 "전체 커맨드(두 카드)" 버튼이 모두 같은 흰색 알약 모양이어서, 지금 어느 카드를 편집 중인지 한눈에 구분되지 않았습니다.

## 2. 변경

- `src/styles.css`의 `.rt-ls-cardseg` 규칙에 카드별 색을 더했습니다. 파랑·주황은 0.82에서 송신기(입력)·수신기(출력) 라벨에 쓴 관례를 따랐습니다.
  - XDM-WOS100 · 월 오버레이(OW): 파랑(`#0057D8`, 사이트 강조색). 선택하면 파랑으로 꽉 채우고 글자는 흰색입니다.
  - XDM-HOS100 · 한 화면 멀티뷰(OQ): 주황(`#C2410C`). 선택하면 주황으로 꽉 채우고 글자는 흰색입니다.
  - 선택하지 않은 쪽도 파랑·주황 글자와 옅은 배경색으로 보여, 두 카드가 서로 다른 색이라는 점이 늘 보입니다.
  - "전체 커맨드(두 카드)" 버튼은 기본 모양(선택 시 흰 알약)을 그대로 둡니다.
- 전체 커맨드 보기 아래의 "WOS100 편집"·"HOS100 편집" 버튼은 같은 `data-ls-card` 속성을 쓰지만 선택기를 `.rt-ls-cardseg` 안으로 한정해 색이 바뀌지 않습니다.
- 다크 모드: 선택하지 않은 버튼의 글자색은 다크 값 생성 도구(`scripts/tools/dark_tokens.cjs --apply`)가 만든 밝은 파랑·주황으로 바뀌고, 선택한 버튼의 꽉 찬 색은 라이트와 같습니다. 다크 블록은 도구 결과와 같습니다(`--check`).
- 스크립트·마크업·커맨드 계산은 바꾸지 않았습니다. 색 규칙만 더했습니다.

## 3. 검증

- 화면 확인: 라이트·다크에서 WOS100·HOS100 선택 상태를 캡처했습니다(`docs/qa/layout-sim-card-colors-0.258/`).
- 화면 시험(`scripts/e2e-smoke.cjs`)에 계산된 색을 확인하는 항목을 더했습니다. HOS100을 고르면 HOS100은 주황 채움·WOS100은 파랑 글자, WOS100을 고르면 반대이며, 두 카드의 선택 색이 서로 다릅니다.
- 단위 테스트의 다크 블록 점검(`tests/dark-mode.test.cjs`)이 계속 통과합니다.

## 4. 되돌리기

`src/styles.css`의 "0.258 출력 카드 선택" 규칙 4줄과 `dark_tokens.cjs --apply`로 만든 다크 두 줄을 지우고 `--apply`를 다시 실행하면 됩니다(PR revert로도 가능).
