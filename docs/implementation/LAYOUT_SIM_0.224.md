## 2. 가이드에서 옮긴 문법 (Command Guide 44~55쪽 "XDM-WOS100 Wall Overlay Command")

```
*255 OW O001-008 W10 H03V02 P4321 [O001…O008 X0Y0W0H0] I001 O001 X0 Y0 W2880 H2160 I002 O002O005 X2880 Y0 W2880 H2160 !
 ID  명령 월 출력 포트 전체  해상도 가로×세로 우선순위  레이어 지우기            창 1                       창 2
```

| 토막 | 뜻 | 시뮬레이터에서 |
|---|---|---|
| `*255` | 시작 + 장비 ID(기본 255, 범용 999) | 장비 ID 입력 |
| `Oxxx-xxx` | 월에 쓰는 출력 포트 전체(슬롯 단위) | 시작 포트(1·5·9…) + 슬롯 수로 자동 |
| `Wxx` | 월 모드 켬 + 출력 해상도(W03~W14 지원, W01·02·15~17 "Not support") | 출력 해상도 선택(미지원은 회색) |
| `HxxVxx` | 디스플레이 가로·세로 수 | 가로·세로 디스플레이 선택 |
| `Pxxxx` | 겹칠 때 포트 우선순위(P4321: 4번이 맨 위) | 겹침 우선순위 선택 |
| `O…X0Y0W0H0` | 모든 레이어 지우기(가이드 예제) / `O000`(현장 메모) | 레이어 지우기 선택(가이드 방식·현장 메모 방식·넣지 않음) |
| `Ixxx Oxxx… Xx Yx Wx Hx` | 입력 번호, 창이 쓰는 출력 포트, 월 전체 픽셀 기준 시작 좌표와 크기 | 창을 끌어 놓거나 표에 숫자 입력 |

- **포트 배치 두 가지**(시뮬레이터 "포트 배치" 선택):
  - **카드 1장 = 디스플레이 1대(OUT 1), 기본값**: 알티컴 확인(사용자 전달 2026-10-13, `docs/implementation/RTCOM_ANSWERS_XDM_0.210.md`) "레이어를 쓰면 WOS100 카드 4포트가 모두 같은 화면을 낸다"와 0.214 레이어 구성도(카드 4장 · 4K 4대)를 따른다. 디스플레이마다 카드 1장을 두고, 그 카드의 포트 1~4를 그 디스플레이 위 창(레이어) 자원으로 쓴다. 2×2 월 = 카드 4장(출력 1~16번).
  - **카드 1장 = 디스플레이 2×2(가이드 연결 그림)**: 46~47쪽 Wall Port Connection 그림대로 카드 1장(포트 4개)이 디스플레이 2×2 블록을 맡고(왼쪽 위 1, 오른쪽 위 2, 왼쪽 아래 3, 오른쪽 아래 4), 블록은 왼쪽→오른쪽, 위→아래로 이어진다. 6×3 월 = 카드 6장, 3행은 카드 4~6의 1·2번 포트만 쓴다(55쪽 예제 8의 O013·O014·O017·O018·O021·O022와 일치). 가이드 예제 1~8이 이 배치로 적혀 있다.
  - 두 배치는 서로 맞지 않는다(가이드 그림은 포트 1~4가 각각 다른 디스플레이, 알티컴 확인은 포트 1~4가 같은 화면). **사용자 확인 2026-10-16(질의서 §5 15번): 현재 기본값 "카드 1장 = 디스플레이 1대"가 실제 배치다.** "디스플레이 2×2"는 가이드 예제 1~8 재현용으로만 남긴다(0.240). 시뮬레이터 각주와 요약 줄에 두 배치의 근거를 적었다.
- **창의 포트**: 창이 걸치는 카드마다 포트 1개를 쓰고, 그 카드에서 아직 쓰지 않은 가장 작은 번호를 고른다. 가이드 예제 1(`I002 O002O005`), 예제 2(`O001O005`), 예제 8(`O013`·`O014`…)이 모두 이 규칙과 맞는다. 카드 1장에는 창 4개까지다.
- **레이어 지우기**: 가이드 오버레이 예제 방식(포트 전체 + `X0Y0W0H0`)과 가이드 LED 예제(56~59쪽) 방식(`O000` 한 토막), 넣지 않음 중 고른다.
- 가이드 47쪽 예제 1과 55쪽 예제 8의 "레이어 지우기" 포트 목록에는 빠진 번호·세 자리 아닌 번호(`O23O24`)가 있어 원문 오타로 보고, 글자 단위 테스트는 목록이 온전한 예제 2·3으로 한다. 기본·비율 예시 프리셋은 규칙으로 계산한 값과 비교한다.
- 가이드는 0.209에서 `output/design/assets/docs/xdm-command-guide.pdf`로 공개되어 있어, 시뮬레이터 각주가 44쪽(PDF 45쪽)으로 링크한다.

## 4. 화면 설명(비개발자용)

1. 월 구성(가로·세로 디스플레이 수, 출력 해상도, 시작 포트)을 고르면 캔버스에 디스플레이 칸과 출력 포트 번호가 그려집니다.
2. "+ 창 추가"를 누르면 입력 영상 창이 생깁니다. 창을 끌어 옮기고, 오른쪽 아래 모서리를 끌어 크기를 바꿉니다. 켜 두면 디스플레이 경계와 ½ 지점에 자석처럼 붙습니다.
3. 아래 표에서 입력 번호·이름·X·Y·너비·높이를 숫자로도 고칠 수 있고, 창이 쓰는 출력 포트가 자동으로 적힙니다.
4. "커맨드" 칸에 완성된 한 줄이 나오고 토막마다 색이 다릅니다(마우스를 올리면 뜻). "복사"로 가져가 RS-232·LAN으로 보냅니다(끝에 Ctrl+Enter).
5. "화면별 표출 영역"에 디스플레이마다 어느 입력의 어느 영역(디스플레이 안 좌표)이 나오는지 적힙니다.
6. 월 밖으로 나가는 창, 크기 0, 겹침, 포트 부족, 미지원 해상도는 경고로 알려 줍니다.

## 5. 현장 메모의 처리

- 0.224: 사용자가 붙여 주신 현장 메모(모니터링 커맨드 3개, HPD·EDID·Genlock 메모)로 `OW` 오버레이 문법이 가이드와 같음을 확인했고, 0.209 결정("제품 사실만 공개 반영")대로 현장 값 자체는 저장소에 적지 않고 22:9 레터박스 계산값(시작 포트 1)만 프리셋으로 두었습니다.
- **0.233(사용자 결정 2026-10-16 "2안으로 전부 공개해")**: 이 항목에 한해 0.209의 비공개를 되돌려 현장 메모를 그대로 공개합니다. 비율 예시 2개를 **현장 메모 원문 프리셋 3개**(출력 9~12번 카드, `O000` 지우기, `*255OWO009-012W14H01V01P4321O000I001O009X0Y295W1920H1571I002O010X1920Y295W1920H1571!` 등)로 바꾸고, 시뮬레이터 아래에 **"알티컴 기술 회신 참고 커맨드(가이드 본문에 없는 현장 확인값)"** 접이식 칸(`FIELD_NOTES`)을 두어 입력·출력 Genlock 절차(2112x1728·3072x1728), HPD 끄기·켜기(`*255IVI001I002I003M03!` → 수백 ms 뒤 `*255IVI001I002M00!` 또는 `*255IVI003M00!`), EDID(`*255IEI009M18!` 3840x1571, `*255IEI009M19!` 3072x1728)를 적었습니다. 현장 이름은 원래 메모에 없어 들어가지 않습니다.
- `IV … M03`과 `IE … M18/M19`는 가이드 본문에 없는 값(가이드 IV는 M00~M02)이라 칸 안에 "알티컴 회신에만 있음"·"표준 펌웨어 여부 확인 중(제조사 질의서 §5 2번)"을 함께 적었습니다.
