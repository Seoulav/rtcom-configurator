## 화면

- 제품 상세 상단 도구 모음의 순서: `← 제품 목록` | `카탈로그 PDF ⤓` | `매뉴얼 PDF ⤓` | `제조사 원본 다이어그램` | `인쇄 / PDF`
- 버튼 한 개는 두 부분으로 나뉩니다.
  - **이름 부분:** `target="_blank" rel="noopener"`로 새 탭에서 열립니다. 브라우저 PDF 뷰어로 보고, 저장·인쇄할 수 있습니다.
  - **화살표 부분:** `download` 속성으로 바로 내려받습니다.
- 팝업을 쓰지 않은 이유: 아이폰 Safari는 iframe 안의 PDF를 첫 쪽만 보여 주거나 확대가 어렵습니다.
- 파일이 없는 종류는 버튼을 숨깁니다. 비활성 버튼은 두지 않습니다.
- 인쇄할 때는 도구 모음 전체가 숨겨집니다(기존 규칙).
- 휴대폰(390px)에서는 줄바꿈되며 가로로 넘치지 않습니다.
- 스크린샷: `docs/qa/product-docs-screens/`

## 데이터

`data/products/<id>.json`의 기존 `documents[]` 항목에 `file`을 더하면 버튼이 생깁니다.

```json
{"type":"Manual","status":"FOUND","title":"HD-13U 사용자 매뉴얼 Ver.1.2","language":"ko","note":"사용자 업로드 공개본(2026-09-28)","file":"hd-13u-manual.pdf"}
```

- **종류(`type`)와 버튼 이름:**
  - `Catalog` → 카탈로그
  - `Manual` → 매뉴얼
  - `ProductSheet` → 제품 안내서
  - 버튼 순서도 이 순서입니다.
- **같은 종류가 둘 이상일 때:** XDM-CT103/CR103처럼 송신기·수신기 매뉴얼이 따로 있으면 `label`(예: `"CT103 매뉴얼"`)을 적어야 합니다.
- **파일 이름:** `<제품 id>-catalog.pdf`, `<제품 id>-manual.pdf`, `<제품 id>-sheet.pdf`
  - 이름에 버전을 넣지 않습니다. 같은 이름으로 덮어쓰면 주소가 유지됩니다.
  - 제품별 이름 표는 `output/design/assets/docs/README.md`에 있습니다.

## 검증 (`scripts/build-product-index.cjs`)

`file`이 있는 문서는 다음을 모두 만족해야 합니다.

- 종류가 Catalog·Manual·ProductSheet 중 하나
- 파일 이름이 제품 id로 시작하고 소문자·숫자·하이픈·점만 쓰며 `.pdf`로 끝남. 예외(0.94): 공용 문서 `rtcom-catalog-2026.pdf`는 Catalog에만 쓸 수 있음
- `page`가 있으면 1 이상 정수(공용 카탈로그는 1~46)
- 파일이 실제로 있음
- 파일 첫 바이트가 `%PDF-`
- 15MB 이하
- 같은 파일을 두 번 등록하지 않음
- 같은 종류가 둘 이상이면 `label`이 있음
- `note`에 "배포 제외·비공개"가 남아 있지 않음 (공개로 바꾼 문서의 옛 표기를 방지)

## 배포 (`scripts/package-site.cjs`)

- `documents[].file`에 등록된 PDF만 `dist/output/design/assets/docs/`로 복사합니다. 폴더에 있기만 하고 등록되지 않은 PDF와 README는 배포하지 않습니다.
- 테스트(`tests/site.test.cjs`)가 확인하는 것:
  - dist 안의 모든 PDF가 등록된 파일
  - 등록된 파일이 모두 dist에 있음
  - 전체 카탈로그 원본이 없음
