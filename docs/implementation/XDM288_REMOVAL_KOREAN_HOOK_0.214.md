# 0.214 XDM-288 공개 라인업 삭제 · 한국어 훅이 중간 진행 안내도 검사

0.214 PR(WOS100 구성도, `WOS_VIDEO_WALL_0.214.md`)에 함께 넣은 두 가지 변경입니다.

## 1. XDM-288 공개 라인업 삭제

**사용자 확인(2026-10-13):** "xdm-216프레임이 가장 큰거야 더 이상은 없어"

0.210~0.213에는 알티컴 답("주문생산방식이야")에 따라 XDM-288을 주문 생산 모델로 공개 라인업에 두고, 0.212부터 `slots` 72·72와 XDM 카드 12종의 `compatibleFrames`에도 넣었습니다. 이번 확인에 따라 모두 뺐습니다.

| 위치 | 변경 |
|---|---|
| `data/products/xdm.json` `lineup` | XDM-288 항목 삭제(메인프레임 6종: XDM-12~XDM-216) |
| XDM 카드 12종 `compatibleFrames` | XDM-288 삭제 |
| `overview` 마지막 문장 | "XDM-288은 주문 생산한다" → "XDM-216이 가장 큰 프레임이다" |
| 출처 `U5`·`U7` 설명 | 삭제 사실과 사용자 확인 문구 추가(기록 보존) |
| `tests/modular-slots.test.cjs` | 구성기에 없는 프레임은 VDM-288X뿐, XDM 라인업에 XDM-288 없음, XDM 카드 호환 목록에 288 프레임 없음 |
| `docs/handoff/AV_PORTAL_MODULAR_SLOTS.md` | AV Portal 안내를 XDM 메인프레임 6종으로 정정 |
| `docs/RTCOM_MANUFACTURER_DATA_REQUEST.md` | §1 XDM-288 자료 요청 행 삭제, §5 5번 답에 확인 추가 |

- **바꾸지 않은 것:** 구성기는 0.29부터 XDM-288을 넣지 않았습니다. 예전에 저장한 XDM-288 구성 파일을 안전하게 여는 코드(`src/core.js`)는 그대로 둡니다.
- **VDM-288X:** 이번 확인은 XDM에 대한 것이므로 VDM-288X(주문 생산, 72·72)는 그대로 둡니다.

## 2. 한국어 훅: 중간 진행 안내도 검사

**사용자 지시(2026-10-13):** "너의 모든 프로세싱과정을 한글로 해야하는 것 고정으로 명시했다 또 영어가 나온다"

0.206의 Stop 훅(`scripts/korean-reply-hook.cjs`)은 마지막 답변만 검사했습니다. 그래서 작업 중간의 진행 안내가 영어여도 마지막 답이 한국어면 통과했습니다.

- **새 검사:** 마지막 사용자 요청 뒤에 쓴 답변 글을 모두 읽습니다(`turnAssistantTexts`). 그중 하나라도 영어 안내(한글 비율 35% 미만, 영어 글자 40자 이상)가 있으면 답을 끝내지 못하게 막습니다.
- **막을 때 안내:** "이번 작업 중 영어로 쓴 진행 안내가 N건 있습니다(예: …)"라고 알리고, 영어로 안내한 내용을 한국어로 다시 정리하게 합니다.
- **무한 반복 방지:** 다시 쓰는 중(`stop_hook_active`)에는 막지 않는 기존 규칙을 그대로 따릅니다.
- **테스트:** `tests/korean-reply-hook.test.cjs`에 "마지막 답변은 한국어지만 중간 안내가 영어면 막음", "이전 요청의 영어 안내는 세지 않음" 검사를 더했습니다.
- **한계:** 이미 보낸 중간 안내를 고칠 수는 없습니다. 훅은 위반을 잡아 바로잡게 하는 장치이고, 처음부터 한국어로 쓰는 것은 모델이 지켜야 합니다.

`docs/implementation/WOS_VIDEO_WALL_0.214.md` "검증" 표와 같은 명령을 함께 실행했습니다. 단위 테스트는 99개입니다.
