# 0.279 제품 링크 주소를 제품 파일 주소로 (카카오톡 미리보기에 제품명)

- 요청: 사용자 2026-11-25 "제품링크에 제품명이 나오면 좋겠다"(카카오톡 대화 캡처: `…/rtcom-configurator/#products/obhd…` 주소가 사이트 첫 화면 카드로 보임).
- 근거: 0.272·0.273에서 만든 `product-<id>.html`(제품별 미리보기 정보) 주소는 카카오톡이 읽을 수 있지만, 주소 뒤 `#`(해시)는 수집기에 전달되지 않습니다. 0.273의 주소창 맞춤은 제품 상세를 연 뒤에만 동작하므로, 카드·관련 제품 링크의 `href` 자체가 `#products/<id>`이면 "링크 주소 복사"·새 탭 열기에서 해시 주소가 그대로 복사됩니다.

## 바뀐 것

| 위치 | 이전 | 이후 |
|---|---|---|
| 제품정보 목록 카드(`src/products.js`) | `href="#products/<id>"` | `href="product-<id>.html#products/<id>"` + `data-product-link` |
| 제품 상세 관련 제품(`src/products.js`) | 같음 | 같음 |
| 구성기 02 "함께 보면 좋은 제품"(`src/app.js`) | 같음 | 같음 |
| AI 검색 답변 제품 링크(`src/ai-search.js`) | 같음 | 같음 |
| 클릭 | 해시 이동 | 문서 클릭 처리가 `location.hash`만 바꿔 같은 화면 이동(보조키·새 탭은 브라우저 기본) |
| 탭 제목 | 첫 화면 제목 유지 | 상세: `제품명 \| RTCOM 제품정보`, 목록·구성기: 첫 화면 제목 |

- 시리즈(XDM·SPX·VDM)도 색인에 있어 `product-xdm.html` 등이 이미 만들어져 있습니다. 구성기의 시리즈 안내 링크(`#products/xdm` 등 새 탭)는 이번 범위에서 두었습니다.
- 상대 경로(`product-<id>.html`)는 `index.html`·`product-*.html`이 같은 폴더에 있어 어디서나 같은 폴더로 풀립니다.

## 한계와 확인

- `#products/…`만 있는 옛 주소를 직접 붙이면 첫 화면 카드로만 보입니다(주소 방식상 해결 불가).
- 카카오톡이 이미 읽은 주소는 한동안 저장된 카드를 보여 줍니다. 카카오 공유 디버거(https://developers.kakao.com/tool/debugger/sharing)에서 "초기화"합니다.
- 이 환경에서는 카카오톡 앱으로 직접 확인할 수 없습니다. 사용자가 제품 카드를 길게 눌러 복사한 주소를 보내 확인해야 합니다.
