# 06 내보내기 개편 — 구성 보고서(PDF)·장비 목록(CSV) (0.172)

## 요청과 결정

- 사용자 요청(2026-09-29): "06 내보내기가 잘 안된다 전반적으로 전체 설계검토해줘 JSON 뭐야?"
- 설계 검토 결과(채팅 보고): JSON 미리보기가 코드 전체를 화면에 쏟아 다운로드 버튼이 약 7,200px 아래로 밀림, JSON 형식이 툴바 "구성 파일 저장"과 같은 파일인데 내보내기 형식처럼 보임, PDF 미리보기(장비 목록만)와 실제 인쇄물(슬롯 표·검토 결과 추가)이 다름, 인쇄물에 내부 근거 코드(G08·M01)·영문 제목·후면 그림 없음, CSV의 행마다 `UNVERIFIED_DRAFT` 반복·장착 위치 없음, 형식 선택이 실행 취소 기록에 쌓임, 파일 이름에 날짜 없음.
- 사용자 선택: "3번부타"(보고서 시안 먼저) → 시안 확인 후 "pdf좋아 그런데 사이트에서 사용하는 애플호환폰트로 인쇄되게해줘".
- 시안에서 열어 둔 선택(표지 칸 입력·서명 칸·작성자 기본값)은 추천안대로 했습니다: 표지 칸은 선택 입력, 서명 칸(작성·검토·승인) 유지, 작성자는 비워 둠(공개 사이트).

## 구현

- `src/app.js`
  - `cardsViewV4({figureOnly:true})`: 03 카드 슬롯의 후면 그림만 돌려준다. 슬롯은 누를 수 없는 `span`이고 × 버튼·드래그가 없다.
  - `reportHtml()`: 미리보기와 인쇄물이 함께 쓰는 보고서. `RtCore.csvRows()`로 장비 목록을 만들고, 검토 결과는 `RtCore.validate()`의 문장만(근거 코드 제외) 오류 → 확인 필요 → 미확정 → 충족 순으로 보인다.
  - 표지 칸은 구성 파일(JSON schema 3)에 넣지 않고 이 브라우저의 `rtcom.report.v1`에만 저장한다. 입력할 때 미리보기만 다시 그려 커서가 유지된다.
  - 저장된 구성의 `format:'JSON'`은 호환을 위해 그대로 읽고, 화면에서는 PDF로 보인다(`checkState`는 바꾸지 않음).
- `src/core.js`: `csvRows()` 추가, `csv()`는 이를 따옴표·수식 방지 처리해 잇는다. 장착 위치는 카드=장착 슬롯, 블랭크=블랭크 슬롯, 전송기=연결한 카드 슬롯(PSE 쌍과 일반 전송기를 구분).
- `index.html`: `#print-report`를 `#rtcom-design` 안으로 옮겼다. 후면 그림 규칙(`#rtcom-design .rt-rack-photo …`)을 인쇄물에서도 그대로 쓰기 위해서다.
- `src/styles.css`: 인쇄 시 `#rtcom-design`의 `#print-report` 밖 자식만 숨긴다(제품정보 인쇄 `html.rt-print-products`는 그대로). 보고서 규칙 `.rt-report`·`.rt-rp-*`를 끝에 추가했다. 쪽 나눔은 강제하지 않고 표의 줄·검토 항목·서명 칸만 쪽 사이에서 자르지 않는다. 인쇄 시 후면 그림 높이는 최대 80mm.
- `src/workspace.inc.js`(초기 이관용 옛 사본, 현재 사이트에서 쓰지 않음)는 이번에 건드리지 않았다.

## 호환성

- `rtcom.configuration.v1`, JSON schema 3, `catalogVersion`, 슬롯 ID는 바뀌지 않았다. 구성 파일 내용도 같다(파일 이름에 날짜만 붙음).
- 새 LocalStorage key `rtcom.report.v1`은 보고서 표지 칸 전용이다. 없거나 읽지 못하면 빈칸으로 둔다.
