# 0.257.0 AMX 코드 잠금 비밀번호 변경 (2026-10-20)

## 1. 요청과 경위

- 사용자 요청 2026-10-20: "AMX커맨드 비밀번호는 (채팅으로 전달한 값)으로 변경해". 직전 질문에서 현재 잠금이 그 값과 일치하지 않음을 확인한 뒤의 요청입니다.
- 0.254.0(2026-10-18, PR #400)에서 다른 세션이 비밀번호를 한 번 바꿨고(원문은 기록에 없음), 이번에 사용자가 다시 정한 값으로 바꿉니다.
- 새 비밀번호 원문은 사용자가 채팅으로 알려 주었으며, 이 문서를 포함해 저장소 어디에도 적지 않습니다.

## 2. 변경

- `scripts/tools/set-amx-password.cjs`로 `src/control-example.js`의 `AMX_LOCK` 한 줄(PBKDF2-SHA256 20만 회, salt·hash)을 새 비밀번호의 변환값으로 바꿨습니다. 기존 변환값은 덮어써서 남지 않으므로 이전 비밀번호는 더 이상 열리지 않습니다.
- 브라우저에서 이미 잠금을 푼 상태(`sessionStorage`의 `rtcom.amxUnlock.v1`)는 변환값 앞 16자와 비교하므로, 새 변환값이 배포되면 열려 있던 모든 화면이 자동으로 다시 잠깁니다.
- 잠기는 범위(AMX NetLinx 코드)와 그냥 보이는 범위(커맨드 문자열·HEX·시뮬레이터 커맨드)는 그대로입니다. 바꾸는 방법은 `node scripts/tools/set-amx-password.cjs "<비밀번호>"`, 확인은 `--check "<비밀번호>"`입니다.

## 3. 경계

- 이 잠금은 브라우저에서 비밀번호를 비교하는 "잠금 스티커"입니다(사용자 결정 2026-10-16). 사이트 코드가 공개되어 있어 개발자 도구를 아는 사람은 우회할 수 있고, 변환값이 공개 저장소에 있어 추측하기 쉬운 비밀번호는 시간을 들이면 알아낼 수 있습니다. 서버 잠금(Cloudflare Worker)은 따로 정해야 합니다.
- 비밀번호가 짧을수록 공개된 변환값을 대상으로 한 추측에 약합니다. 더 긴 비밀번호가 필요하면 같은 도구로 다시 설정합니다.

## 4. 검증

- `set-amx-password.cjs --check`: 새 비밀번호 "일치", 이전 비밀번호(0.239 값) "일치하지 않습니다".
- 단위 테스트의 `AMX_LOCK` 형식 시험(원문 없이 변환값)과 화면 시험의 잠금·해제 흐름(시험용 비밀번호로 dist만 바꿔 실행)은 기본 검증 명령으로 확인합니다.

## 5. 되돌리기

같은 도구로 다른 비밀번호를 설정하거나 PR을 되돌립니다. 되돌리면 이 변경 이전 변환값(0.254.0 값)으로 돌아가며 그 비밀번호 원문은 기록에 없습니다.
