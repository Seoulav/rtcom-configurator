# 전송기 자동 연동과 전송기 단계 개편 (0.9.0)

- 요청:
  - "전송기 관련해서 정보가 없네. HDBaseT, fiber 입출력 카드에 연동되는 전송기가 있으니까 그거는 나와야 해"
  - "CIS, COS 카드는 CTR100과 호환되니까 연동되게 해 줘. 광은 FT101, FR101"
- 기준 커밋: `4d089be` (0.8.0 병합)

## 원인

0.8까지 전송기 단계는 HDBaseT(CAT)·광(FIBER) 카드가 장착된 슬롯에만 이름뿐인 드롭다운을 보여 주었습니다. 이런 카드가 없으면 "CAT 또는 광 카드를 장착하면…" 한 줄만 나와서, 어떤 전송기가 있는지 알 수 없었습니다. 카드를 장착해도 전송기는 사용자가 직접 골라야 해서 BOM에 빠지기 쉬웠습니다.

## 근거 (RTCom 종합 카탈로그)

| 카드 | 기본 연동 전송기 | 대안 | 근거 |
|---|---|---|---|
| XDM-CIS100 | XDM-CTR100 · TX | XDM-CT103 (벽부형) | p.10 "송신기로 변환 후 XDM-CIS100과 호환", p.11 |
| XDM-COS100 | XDM-CTR100 · RX | XDM-CR103 (벽부형) | p.10 "수신기로 변환 후 XDM-COS100과 호환", p.11 |
| XDM-FIS100 | XDM-FT101 | - | p.12 "XDM-FT101은 XDM-FIS100과" |
| XDM-FOS100 | XDM-FR101 | - | p.12 "XDM-FR101은 XDM-FOS100과" |

## 변경

- `src/core.js`: `defaultLink(카드, 채널 수)`를 추가했습니다. 위 표의 기본 전송기를 `{device, count, distance}`로 돌려주며, 기본값은 항상 기존 `choices()` 안에서만 고릅니다.
- `src/app.js`:
  - 카드를 장착하면 `defaultLink`로 전송기를 카드 채널 수(4)만큼 자동 연결합니다. 다른 카드로 바꾸면 해당 카드 기준으로 다시 정하고, 전송기가 없는 카드면 연결을 지웁니다.
  - 전송기 단계(`linksViewV3`)
    - 카드마다 전송기를 사진 타일(모델, 역할, 핵심 사양 3줄)로 선택하고, "연결하지 않음"과 채널 수 선택을 둡니다.
    - 전송기 사양 값은 카탈로그 p.10~12 원문에서 옮겼습니다.
    - 화면 아래에는 연동 전송기 라인업 6종을 항상 표시합니다. CTR100 PSE는 선택 항목이 아니라 전원 검토용 안내입니다.
    - HDBaseT·광 카드가 없으면 안내 문구와 "카드 슬롯으로 돌아가기" 버튼을 보여 줍니다.
  - 저장되는 전송기 이름(`XDM-CTR100 · TX` 등)은 그대로라 BOM, 검증, CSV, 기존 JSON과 호환됩니다.
- `output/design/assets/extenders/`: 카탈로그 PDF에서 추출한 전송기 사진 6장(투명 배경 WebP, 각 3~6KB)입니다. 추출 스크립트는 `scripts/tools/extract_catalog_extenders.py`입니다.

## 자동 연결을 적용하지 않는 경우

- 이미 저장된 구성(LocalStorage), 불러온 JSON, 실행 취소·다시 실행으로 되돌린 상태에는 적용하지 않습니다. 사용자가 카드를 새로 장착하는 순간에만 적용합니다.
- SPX·VDM은 기본 연동 표가 없어 기존 동작을 유지합니다.

## 되돌리는 방법

이 PR의 병합 커밋을 revert하면 0.8.0으로 돌아갑니다. 저장 형식이 같아서 0.9에서 저장한 구성도 0.8에서 그대로 읽힙니다.

## 남은 확인

- CTR100을 PSE 없이 쓸 때의 전원 방식(개별 전원 어댑터 포함 여부)은 제조사 확인이 필요합니다. 현재는 기존 규칙대로 "별도 POE Power Supply 필요" 경고를 표시합니다.
- CT103·CR103을 XDM 슬롯 POE로 쓸 때 슬롯당 급전 가능 수량은 카탈로그에 없어 제조사 확인이 필요합니다.
