## 1. PDF 변환(`scripts/tools/docx_manual_to_pdf.py`)

| 단계 | 내용 | 이유 |
|---|---|---|
| 글꼴 | DOCX 복사본에서 Noto Sans KR 내장 글꼴 참조를 지우고, Google Fonts의 Noto Sans KR(400·500·700·800, OFL)을 Word 문서가 부르는 이름으로 바꿔 씀 | Word 내장본은 쓰인 글자만 남긴 가변 글꼴이라, LibreOffice가 가장 가는 굵기(Thin)로 그리고 일부 글자(항목·이송·보관 등)를 상자(☒)로 냈음 |
| 쪽 나눔 | Word가 남긴 쪽 위치(`lastRenderedPageBreak`)를 실제 쪽 나눔으로 바꿈. 표 안, 바로 앞에 쪽·구역 나눔이 있는 위치는 건너뜀. "목차" 단락 앞에 글이 있으면 쪽 나눔 추가 | LibreOffice가 Word보다 줄을 촘촘히 그려 쪽이 밀리고(목차 쪽 수와 1쪽 차이), 표·제목이 쪽 사이에 갈렸음 |
| 변환 | LibreOffice 24.2 `soffice --headless --convert-to pdf` | 작업 환경에 Writer가 없어 `libreoffice-writer`를 설치함 |
| 속성 | 제목만 남기고 작성자(`user`, MR-4S는 개인 이름)·만든 프로그램·변환 프로그램·날짜·XMP 삭제(PyMuPDF) | 0.209 커맨드 가이드와 같은 공개 기준 |

- **결과:** 5건 모두 각 매뉴얼 목차의 마지막 쪽 번호와 쪽 수가 같습니다. 이미지·표·번호 설명이 원본 순서대로 들어 있습니다.
- **원본과 다른 점:** 일부 표가 다음 쪽으로 이어지는 위치는 원본 목차의 쪽 범위 안에서 조금 다를 수 있습니다.
- **재현:** 스크립트로 HD-D102U·MR-4S를 다시 만들어 공개본과 본문 글이 같은지 확인했습니다.

## 2. 매뉴얼 기준 값 반영

| 제품 | 바뀐 곳(출처 `M`, MR-4S·FT103은 매뉴얼 표기) |
|---|---|
| HD-D102U | 전원 DC 5V 1A → 2A(사양·단자 지도). 사양에 규격 HDMI 2.0, HDCP 2.2, EDID 전면 스위치 STD(내장 3840x2160 @ 60Hz)·TV(출력 1번 EDID 복사) 행 추가. 05 스마트 EDID 문구 구체화 |
| CT101-U / CR101-U | 전원 DC +12V 2A → 1A 이상(사양·단자 지도). 규격 두 행(DVI 1.0, HDMI 1.4b / HDMI 1.4)을 매뉴얼 값 "HDMI 1.4, HDBaseT" 한 행으로. RS-232 단자 "피닉스(핀 수 미기재)" → 피닉스 3핀. 송·수신기 USB 펌웨어 포트 행 추가. 오디오 병합은 입력이 DVI 신호일 때(05·단자 지도). VDM CIS4-U·COS4-U 연동(05). CR101-U 무게 0.27kg 유지 |
| CT104-U / CR104-U | 전원 DC +12V 2A → 1A 이상(사양·단자 지도). 크기 한 행 → CT104-U 112×72×26mm, CR104-U 113×73×29mm. RS-232 단자 피닉스 3핀. VDM CIS4-U·COS4-U 연동(05) |
| MR-4S | 크기 439×170×44 → 440×171×42.2mm. 작동 온도·습도 0~40℃·80% 미만 → 10~40℃·10~80%(응결 없음). 전원 조건 "전원 어댑터 2개 포함(POWER 1·2)". "장착 모듈: XDM-CTR100(CATx), XDM-FT101/FR101(광) · 매뉴얼 v1.00 기준 · XDM 매트릭스 호환" 행. 개요·05·관련 제품(XDM-CTR100·XDM-FT101/FR101·XDM Series) |
| FT103-U-H / FR103-U | 전원 "DC +12V 2A(조건 1A 이상)" → "DC +12V 1A 이상". 나머지는 기존 근거 M1(Ver.1.4)과 같음 |

- **문서 버튼:** 5개 제품 상세에 `Manual` 문서(`preview: "pdfjs"`)를 등록했습니다. FT103은 "배포 제외"로 두었던 기존 항목을 공개본으로 바꿨습니다.
- **해상도:** CT101·CT104·FT103 매뉴얼의 `4096x2160` 표기는 0.182 결정(화면은 3840x2160 기준)에 따라 사이트에 옮기지 않았습니다. 공개 PDF에는 원문 그대로 있습니다.
- **MR-4S 장착 모듈 확인 필요:** 기존 카탈로그 뒷면 사진(구 Digital Extender 표기)의 모듈 라벨은 CR104-U 계열로 보입니다. 그래서 장착 모듈 행 조건에 "매뉴얼 v1.00 기준"을 적고, VDM 계열 모듈 장착 여부를 알티컴 질문 13번으로 남겼습니다(`docs/RTCOM_MANUFACTURER_DATA_REQUEST.md` §5).

## 3. 한국어 검사: 도구 실행 직전에도 검사(PreToolUse 훅)

사용자 지시(2026-10-14): "진행과정은 한글로 해줘 계속 규칙을 어긴대". 이번 작업 중에 진행 안내와 마지막 보고를 영어로 쓴 일이 있었습니다. 0.214 Stop 훅이 이를 잡았지만, 답을 끝낼 때만 검사하므로 이미 화면에 나간 뒤였습니다.

- **새 검사:** `.claude/settings.json`에 `PreToolUse` 훅을 더했습니다. 도구를 실행하기 직전에 이번 요청에서 가장 최근에 쓴 진행 안내를 잽니다(`scripts/korean-reply-hook.cjs`, 기준은 Stop 훅과 같음: 영어 글자 40자 이상, 한글 비율 35% 미만).
- **영어일 때:** 그 도구 실행을 막고(`permissionDecision: "deny"`), 같은 안내를 한국어로 다시 쓴 뒤 실행하게 합니다. 한국어로 다시 쓰면 가장 최근 안내가 바뀌어 통과합니다.
- **한계:** 도구를 실행하는 순간에는 바로 직전 안내가 아직 대화 기록에 저장되지 않은 경우가 있습니다(이 세션에서 확인). 그래서 영어 안내는 그 다음 도구 실행에서 막힙니다. 답을 끝낼 때의 Stop 훅 검사는 그대로입니다.
- **테스트:** `tests/korean-reply-hook.test.cjs`에 4가지 검사를 더했습니다.
  - 영어 안내 뒤에는 막음
  - 한국어로 다시 쓰면 통과
  - 코드만 있는 안내는 통과
  - 안내가 없으면 통과
  - 설정 파일이 `PreToolUse` 훅을 연결하는지도 검사합니다.
