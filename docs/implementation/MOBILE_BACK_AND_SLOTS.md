# 휴대폰 슬롯 겹침·뒤로가기 404 수정 (0.14.0)

- 제보(2026-09-26, 휴대폰 스크린샷 2장): "슬롯에 카드가 아직도 짤리고 뒤로가기하면 404에러 자주 나"
- 기준 커밋: `9cd059f` (main, 0.13.0 병합)

## 1. 슬롯 겹침으로 카드가 잘림

- 원인: `styles.css`의 `@media(pointer:coarse){#rtcom-design button{min-height:44px}}`(터치 기기 누름 영역 기준)가 슬롯 버튼에도 적용됐습니다. 416px 폭 휴대폰에서 SPX-M3236 입력 슬롯 한 칸은 약 20px인데 44px로 늘어나, 입력 4칸이 21px 간격으로 겹쳤습니다(아래 슬롯이 위 슬롯을 덮음). 데스크톱 브라우저에는 이 규칙이 적용되지 않아 기존 e2e가 놓쳤습니다.
- 수정: `@media(pointer:coarse){.rt-rack .rt-rack-slot, .rt-rack-photo .rt-rack-slot{min-height:0}}`. SPX 가로 카드 사진(`.rt-rack-photo.rt-rack-hs`)의 최소 폭 420px를 풀어 화면 폭에 맞춥니다. 사진 슬롯 간격은 1px로 통일했습니다.
- 한계: 휴대폰에서 SPX-M3236 슬롯 한 칸 높이는 약 18px로 작습니다. 누르기 어렵다면 화면 확대(핀치)를 쓰거나 후속으로 확대 보기 기능을 검토합니다.

## 2. 뒤로가기 404

- 원인: 구성기는 한 화면 안에서 단계를 바꾸고 브라우저 방문 기록을 남기지 않았습니다. 휴대폰 뒤로가기는 구성기 이전에 방문한 주소로 나가며, 그 주소가 예전 경로·없는 파일이면 GitHub Pages 404가 떴습니다.
- 수정(`src/app.js`):
  - `syncNavHistory()`: 첫 화면에서 `replaceState`, 단계가 바뀔 때마다 `pushState({rtStep})`. 주소 인자는 항상 `location.href`라 주소·상대 경로 이미지에는 영향이 없습니다(0.7의 P0 이미지 깨짐 재발 방지 테스트를 "주소 유지 시에만 허용"으로 조정).
  - `popstate`: 기록의 단계로 돌아갑니다(열린 카드 선택 창은 닫음). 카드 선택 창 자체는 기록을 남기지 않습니다. 비동기 `history.back()` 정리 방식은 단계 이동과 경합해 기록 순서가 꼬여서 쓰지 않았습니다.
- 수정(`scripts/package-site.cjs`): `dist/404.html`을 만들어 `/rtcom-configurator/`(또는 `/rtcom-av-design/`) 아래 없는 주소를 구성기 첫 화면으로 보냅니다.
