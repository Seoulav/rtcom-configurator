# XDM 화면 연출 시뮬레이터 2차 — HOS100 한 화면 멀티뷰(OQ) (0.225.0)

## 1. 요청과 결정

- 사용자 요청 2026-10-16 "다음 단계 진행해줘"(0.224 보고의 다음 단계 제안 2번 "2차: HOS100 한 화면 사용자 레이아웃·PIP"). 1차(`docs/implementation/LAYOUT_SIM_0.224.md`)와 같은 카드 안에 출력 카드 전환 버튼(WOS100 · HOS100)을 두고 HOS100 모드를 더했다.
- 공개 범위는 1차 결정(전부 공개) 그대로. 근거는 0.209에서 공개한 XDM Command Guide 25~29쪽 `[OQ] Output Quad view Setting Command`.

## 2. 가이드에서 옮긴 문법 (Command Guide 25~29쪽)

| 레이아웃 | 커맨드 | 뜻 |
|---|---|---|
| 사용자 배치 `L00` | `*255OQ O001 M14 L00 P4321 O001 X0000 Y0000 W0960 H0540 O002 … O004 …!` | 카드 1번 포트에 합성 화면, 창 1~4 = 카드 포트 1~4, 좌표·크기는 출력 해상도 안의 픽셀(4자리), `W0 H0`은 창 끄기, `P`는 겹침 순서 |
| PIP 사용자 배치 `L09` | `*255OQ O001 M14 L09 X1920 Y1080 W1920 H1080!` | 창 1 전체 + 창 2(포트 2) 위치·크기 |
| 고정 `L01~L08`·`L10~L12` | `*255OQ O001 M14 L05!` | 쿼드뷰·위 1 아래 3·왼쪽 1 오른쪽 3·PIP 고정·PBP 전체·PBP 16:9·1~4번 PIP 고정·창 n 전체 |
| 끄기 | `*255OQ O001 M00!` | 일반 스위칭으로 |
| 입력 연결 | `*255C I001 O001, I002 O002 …!` | 창 n에 나올 입력을 카드 포트 n에 연결(12쪽 스위칭 커맨드, 쉼표로 여러 쌍) |

- `M` 코드는 WOS100의 `W` 코드와 같은 해상도 표(M01~M17)라 `TIMINGS`를 함께 쓴다. OQ에는 "Not support" 표시가 없어 모두 고를 수 있다.
- `L13`(1~4번 PIP 사용자 배치)은 가이드 25쪽 형식에 좌표 묶음이 2개만 적혀 있어(창 2·3·4 중 어느 창인지 불분명) 넣지 않았다. 알티컴 확인 뒤 추가한다.
- 포트 상태(서울영상테크 확인 2026-10-12, 0.205·0.209 HOS100 팝업과 같은 규칙): 레이어 4개(또는 3개) → 1번 합성, 2~4번은 1번과 같은 화면 / 2개(PIP·PBP) → 1번 합성, 2번 사용 불가, 3·4번은 따로 스위칭 / 1개 → 전체 화면 스위칭. L00은 켜진 창 수(W·H > 0)를 레이어 수로 센다.

## 3. 만든 것

- `src/layout-sim.js`: `HOS_LAYOUTS`(13종, 고정 레이아웃 미리보기 칸은 가이드 28쪽 그림과 `src/app.js` HOS100 팝업의 배치를 따른 대략값), `normalizeHos`, `hosWindows`(레이아웃별로 보이는 창과 끌 수 있는 창), `hosPortStatus`, `hosCommandFor`(스위칭 커맨드 + 레이아웃 커맨드 + 끄기 커맨드, 경고), `HOS_PRESETS`(가이드 예제 4개 + 기본 4분할 좌표).
- 화면: 카드 전환 버튼(WOS100 · HOS100, 선택은 브라우저에 저장), HOS100 모드에서 레이아웃·출력 해상도·카드 시작 포트·겹침 우선순위(L00만)·장비 ID·맞춤·프리셋. 캔버스는 디스플레이 1대이고 L00은 창 4개, L09는 창 2만 끌 수 있으며 고정 레이아웃은 점선 창으로 보여 주고 끌 수 없다. 표에 창마다 포트 번호·입력·이름·좌표와 포트 상태. 커맨드 칸은 "① 입력 → 포트 연결", "② 멀티뷰 레이아웃", "멀티뷰 끄기" 세 줄이고 복사는 ①·②를 복사한다.
- **겹침 순서와 "맨 위로"**(사용자 질문 2026-10-16 "화면이 겹쳤을때 최상단으로 하는 기능이있어?"): 장비는 우선순위 `P`(P4321: 포트 4번 창이 맨 위, P1234: 1번이 맨 위)와 창이 받은 포트 번호로 겹침 순서를 정한다. 시뮬레이터 표에 "겹침" 열(위에서 몇 번째)과 "맨 위로" 버튼을 넣었다. WOS100은 포트가 창 순서대로 배정되므로 창을 맨 뒤(P4321) 또는 맨 앞(P1234)으로 옮기고(`bringToFront`), HOS100 L00은 창 n = 포트 n이라 맨 위 자리와 입력·좌표를 맞바꾼다(`hosBringToFront`, 입력 연결 커맨드도 함께 바뀜). 캔버스의 겹침도 같은 순서(`stackOrder`)로 보이게 바꿨다(1차의 "작은 창 위" 임시 규칙 대체). 가려진 창은 표에서 숫자로 고치거나 "맨 위로"로 올린다.
- `src/products.js` 카드 제목·안내 문장에 HOS100(OQ) 추가. `src/styles.css` `rt-ls-cardseg`·`is-fixed`·`rt-ls-cmdline` 등.
- `docs/RTCOM_MANUFACTURER_DATA_REQUEST.md` §5에 15번(WOS100 오버레이 포트 배치)·16번(L13 좌표 묶음) 질문 추가.

## 5. 되돌리기

카드 전환 버튼과 `renderHos`는 `card==='HOS100'`일 때만 쓰인다. `src/layout-sim.js`에서 `cardSeg()` 호출과 `if(card==='HOS100'){renderHos();return}` 한 줄을 빼면 1차(WOS100) 화면만 남는다. 저장된 값은 브라우저 `localStorage` 키 `rtcom.layoutSim.hos.v1`·`rtcom.layoutSim.card.v1`에만 있다.

## 6. 남은 것

- `L13` 사용자 PIP 4창 형식(알티컴 확인), WOS100 LED 월(`S/L` 모드), 03 카드 슬롯 신호명을 창 이름으로 자동 채우기, VDM·SPX 격자 월·쿼드뷰(`docs/handoff/OPEN_ITEMS.md`).

## 7. 0.226.0 보완 — 두 카드를 한 구성에(전체 커맨드)

- 사용자 요청 2026-10-16 "HOS카드에서 연출예시와 WOS카드 연출예시 둘다 선택하고나서 가능하게 해줘". 뜻을 물은 뒤 답: HOS 카드로 모니터 1대에 입력 2개·4개를 연출하고 WOS 카드로 디스플레이 4대에 걸친 레이어를 연출하는 식으로 **둘 다 쓰는 현장이 있어, 각 카드의 커맨드 구성을 골라 볼 수 있어야 한다**.
- `combinedCommands(wos,hos,include)`: 포함한 카드의 커맨드를 보내는 순서대로 모은다(WOS100 `OW` → HOS100 `C` → `OQ`). 두 카드의 출력 포트 범위가 겹치면(`overlap`) 경고와 함께 `nextFreePort`(WOS100 마지막 포트 + 1)를 돌려준다. 포함한 카드가 없으면 경고.
- 화면: 카드 전환 버튼에 "전체 커맨드(두 카드)"(`card==='ALL'`), "WOS100 포함 / HOS100 포함" 체크(`include`, 브라우저 저장 키 `rtcom.layoutSim.include.v1`). 전체 보기는 두 카드의 작은 그림(디스플레이 칸·포트 번호·창)과 "편집" 버튼, 번호를 붙인 커맨드 줄, "전부 복사", 겹침 때 "HOS100 시작 포트를 N번으로" 버튼.
- 검증: `tests/layout-sim.test.cjs` 0.226(두 카드 3줄·겹침 경고·17번·HOS만·포함 없음), e2e(전체 보기 3줄 → 버튼으로 17번 → 경고 사라짐·커맨드 O017), 화면 `docs/qa/layout-sim-both-0.226/`.
- 되돌리기: `cardSeg()`의 세 번째 버튼과 포함 체크, `if(card==='ALL'){renderAll();return}`을 빼면 0.225 화면으로 돌아간다.

## 8. 0.229.0 보완 — 레이어 번호 표기(1 = 맨 위)

- 사용자 요청 2026-10-16(공개 화면 `#products/xdm` HOS100 L00 화면을 보며 "layer순서를 표기하는게 좋겠어. 최상단을 1번에 하는건 어때?"). 창 4개가 겹칠 때 어느 창이 위인지 캔버스에서 바로 보이지 않았고, 표의 "위에서 N번째" 표기는 번호 체계가 없었다.
- 캔버스: WOS100·HOS100(L00·L09 PIP) 창마다 오른쪽 위에 `레이어 N` 배지(`.rt-ls-win-layer`)를 붙인다. 1이 맨 위이고 맨 위 배지는 창 색으로 채운다(`is-top`). 번호는 보이는 창(W·H > 0)만 세며 계산은 기존 겹침 순서(WOS100 `stackOrder`: P와 포트 번호 / HOS100 L00: P4321이면 창 4 → 1, P1234면 창 1 → 1 / L09: PIP 창 2가 1)와 같다. 고정 레이아웃(L01~L08·L10~L12)은 창이 겹치지 않아 배지를 붙이지 않는다. WOS100 창 태그에도 HOS100처럼 `창 N ·`을 앞에 붙여 표와 맞췄다.
- 표: "겹침" 열 이름을 "레이어(1 = 맨 위)"로 바꾸고 칸을 `레이어 N`(맨 위는 `· 맨 위`)으로 적는다. "맨 위로" 버튼과 `P` 우선순위 선택은 그대로다.
- 검증: e2e에서 WOS100 기본 배치(P4321, PIP가 포트 14)의 배지가 `레이어 2, 레이어 1`이고 맨 위 배지가 창 2에 붙는지, HOS100 L00 기본(P4321)의 배지·표가 `레이어 4·3·2·1`인지 확인한다. 화면: `docs/qa/layout-sim-layers-0.229/`.
- 되돌리기: `src/layout-sim.js`의 `rt-ls-win-layer` span 두 곳과 표 칸 문구, `src/styles.css`의 `.rt-ls-win-layer` 두 줄을 빼면 0.226 표기("맨 위"·"위에서 N번째")로 돌아간다.
