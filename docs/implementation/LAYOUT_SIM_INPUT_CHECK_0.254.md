# 0.254.0 화면 연출 시뮬레이터 입력 번호 안내·연결 한 줄·꺼진 창 표시 (2026-10-18)

## 1. 요청과 결정

- 사용자 질문 2026-10-18: "HOS카드 2분할 화면 연출시 출력1번 슬롯카드에 입력 레이어시 그 입력이 몇 번인지 어떻게 지정하고 알 수 있는거지? 내가 해석이 안되는거 같아", 캡처를 보내며 "빨간색 테두리 부분이 입력포트 인거야?"라고 확인했습니다.
- 답: 표의 "입력" 칸이 매트릭스 프레임의 입력 포트 번호(구성기 03 카드 슬롯의 CH 번호, 커맨드의 `I005`는 입력 5번)입니다. 번호가 창·포트·입력·레이어 4종류라 헷갈린다고 보고 개선안 3가지를 제안했고, 사용자가 "제안대로 진행해줘"라고 답했습니다.

## 2. 변경 (`src/layout-sim.js`, `src/styles.css`)

- **꺼진 창 표시(HOS100):** 너비·높이가 0이거나 그 레이아웃이 쓰지 않는 창(예: PBP 전체 L10의 창 3·4)은 행을 흐리게 하고 "꺼짐" 표시를 붙입니다. 그 창의 입력은 연결 커맨드(`*255C…!`)에도 이미 들어가지 않았고, 표에도 "커맨드에 들어가지 않습니다"라고 알려 줍니다. 쓸모없는 "맨 위로" 버튼은 꺼진 창에서 숨깁니다.
- **입력 번호 확인(HOS100·WOS100):** 구성기가 이 브라우저에 저장한 구성(`rtcom.configuration.v1`)이 XDM이면, 입력 슬롯의 카드가 덮는 채널(CH)을 구성기의 `chRange`와 같은 공식(첫 채널 = (슬롯 번호 − 1) × XDM 입력 카드 최대 채널 수 + 1)으로 계산해 켜진 창의 입력 번호가 그 범위 안인지 확인합니다. 범위 밖이면 입력 칸에 주황 테두리를 두고 경고를 보입니다. 다른 구성으로 시험하는 중이면 무시하면 됩니다. 저장된 구성이 없거나 XDM이 아니면 경고 없이 안내 문구만 보입니다.
- **연결 한눈에 보기:** 표 아래에 `창 4 ← 입력 10 (이름) → 포트 O004`처럼 줄마다 연결을 보여 줍니다. WOS100은 창이 받은 출력 포트 전부를 적고(카드 1장 = 디스플레이 1대라 카드마다 첫 포트, 0.240), HOS100은 꺼진 창도 "꺼짐" 줄로 남깁니다.
- **입력 칸 설명:** 표 머리글 "입력"에 마우스를 올리면 "매트릭스 입력 포트 번호입니다. 구성기 03 카드 슬롯의 CH 번호와 같고, 커맨드의 I005는 입력 5번입니다."가 보이고, 표 아래에 같은 설명 한 줄이 있습니다.
- 같은 경고 목록에 있던 겹침 문구의 조사 오류(`창 2과 창 3이`)를 `겹치는 창: 창 2, 창 3.`으로 고쳤습니다(HOS100·WOS100).
- 새 함수(`savedInputChannels`·`inputProblems`·`hosUsed`·`hosLinks`·`wosLinks`)는 모두 계산만 하는 함수라 `RtLayoutSim`으로 내보내 시험합니다.

## 3. 경계

- 시뮬레이터는 소스가 실제로 어느 입력에 꽂혔는지 알지 못합니다. 입력 번호는 사용자가 정하는 값이고, 구성기 구성은 "있는 채널 범위"만 알려 줍니다.
- 구성기 저장 구성은 이 브라우저 저장소에 있는 값입니다. 다른 PC·브라우저의 구성은 읽지 못합니다. 읽기만 하고 쓰지 않으며 저장 형식(schema 3)은 그대로입니다.
- 전체 커맨드(두 카드) 보기는 바꾸지 않았습니다.

## 4. 검증

- 단위 테스트 191개 통과: 구성기 CH 공식(구간 합침, 빈 슬롯 구간 나눔, XDM이 아니면 null)과 구성기 `chRange` 공식 소스 확인, 없는 입력만 경고, HOS100 꺼진 창이 연결 커맨드에서 빠짐(`*255CI002O003,I010O004!`), PBP 전체 L10의 창 3·4 제외, 시작 포트 5이면 창 4는 포트 8, WOS100 연결 포트 `[1,5,9,13]`.
- 화면 시험 286/286 통과: 입력 칸 설명, 연결 4줄, 창 1 끄기 → 꺼짐 표시·맨 위로 버튼 없음·커맨드에서 `I001O001` 사라짐, 구성기 구성(입력 CH 1–8) 저장 뒤 입력 10에서 경고, WOS100 화면의 같은 안내.
