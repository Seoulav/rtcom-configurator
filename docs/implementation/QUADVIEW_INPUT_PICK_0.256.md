# 0.256.0 VDM 쿼드뷰 시뮬레이터 입력 선택 목록 (2026-10-18)

## 1. 요청

- 사용자 요청 2026-10-18: 0.255 보고의 다음 단계 제안 "VDM 시뮬레이터에도 입력 선택 목록 적용"에 "2번도 진행해". 이어서 사용자가 구성기 03 카드 슬롯 캡처(VDM-16X, 입력 카드 HIS4-U 4장)로 "여기를 말하는거야?"라고 물어, 목록의 정보 출처(구성기)와 바뀌는 화면(제품정보 VDM 07 쿼드뷰 시뮬레이터)이 다르다는 점을 설명한 뒤 진행했습니다.

## 2. 변경 (`src/quad-view.js`, `src/layout-sim.js`, `src/styles.css`)

- **선택 목록:** 제품정보 VDM "07 쿼드뷰 시뮬레이터"의 "② 칸마다 넣을 입력"(C1~C4)이, 구성기에 저장된 VDM 구성에 입력 카드가 있으면 숫자 칸 대신 채널 목록 선택으로 바뀝니다. 한 줄은 `입력 5 · IN 2 · HIS4-U · CAM1`(채널 · 입력 슬롯 · 카드 · 신호명)입니다. 캡처 구성(HIS4-U 4장)이면 입력 1~16이 나옵니다.
- **연결 커맨드:** 입력을 고르면 입력 연결(C) 명령이 바로 바뀝니다(예: C2에 입력 5 → `*255CI05O06!`). 입력 연결 명령, 레이아웃, 타이밍 등 커맨드 문자열 규칙은 그대로입니다.
- **직접 입력:** 목록 마지막의 "직접 입력…"을 고르면 그 칸만 숫자 칸으로 바뀌고 "목록" 버튼으로 되돌립니다. 구성에 없는 번호는 `입력 50 · 구성기에 없음`으로 남고 주황 테두리와 경고(`C4 칸(입력 50): 구성기에 저장된 VDM-16X 구성에는 입력 50번이 없습니다…`)가 나옵니다.
- **구성이 없으면** 지금처럼 숫자 칸이고 안내 문장만 보입니다. 이름 칸이 없는 화면이라 신호명 자동 채움은 없습니다.
- **공용 계산:** `RtLayoutSim.savedInputChannels(doc,catalog,family)`가 프레임 종류(`'XDM'` 기본, `'VDM'`)를 받습니다. 구성기 `chRange`는 종류와 상관없이 같은 공식이라 같은 계산을 씁니다. `inputProblems`는 경고에 쓰는 이름(창 대신 `C2 칸`)을 받을 수 있게 했습니다(기본은 예전처럼 `창`).

## 3. 경계

- 구성기 저장 구성은 읽기만 하며 저장 형식(schema 3)과 커맨드 문자열은 그대로입니다. 다른 PC·브라우저의 구성은 읽지 못합니다.
- 출력 카드·전송기는 목록에 넣지 않습니다(입력 카드 채널만). VDM 비디오 월 탭의 출력 번호는 입력이 아니라 바꾸지 않았습니다.
- "직접 입력" 상태는 화면을 다시 불러오면 목록으로 돌아갑니다.
- 입력 연결(C) 명령의 출력 번호(카드 첫 출력 포트)는 알티컴 확인 대기(질문 29번)라는 기존 안내가 그대로입니다.

## 4. 검증

- 단위 테스트: VDM 구성에서 16채널 목록·`CH 1–16`·카드·신호명, 출력 카드 제외, 다른 프레임 종류 구성은 읽지 않음, 경고 이름 변경, XDM 기본 동작 유지, 화면 소스 연결.
- 화면 시험: 저장된 구성이 없으면 숫자 칸 4개, 있으면 목록 4개(옵션 17개: 채널 16 + 직접 입력), C2에 입력 5를 고르면 연결 커맨드 `*255CI05O06!`과 범례 `C2 ← 입력 5`, 직접 입력 전환·50 입력 시 경고·목록 복귀(`구성기에 없음`), 가로 넘침 없음.
