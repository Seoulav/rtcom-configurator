# SPX 실제 슬롯 구성 (0.10.0)

- 요청: "VDM도 XDM처럼 개선하자" + SPX 자료 압축 파일 + SPX 고해상도 사진(채팅 첨부)
- 결정(사용자, 2026-09-26): SPX 카드 이름은 현재(HIS8·HOS10·HOS12·COS12) 유지, 작업 순서는 SPX → VDM, PR #7 병합은 보류
- 근거: 근거 문서 U05

## 슬롯 구성

| 모델 | 입력 슬롯(8포트) | 출력 슬롯(10~12포트) | 근거 |
|---|---|---|---|
| SPX-M810 | 1 | 1 | 후면 사진, 매뉴얼 p.4 |
| SPX-M1620 | 2 | 2 | 카탈로그 16×20을 카드 포트 수로 나눈 계산값 |
| SPX-M3236 | 4 | 3 | 후면 사진 |
| SPX-M2472 | 3 | 6 | 매뉴얼 p.4 "최대 6개 카드, 72포트" |
| SPX-M24120 | 3 | 10 | 매뉴얼 p.4 "최대 10개 카드, 120포트" |

- M1620은 사진이나 문장 근거가 없는 계산값입니다. 후면 사진을 받으면 확인합니다.
- M810의 최대 I/O는 8×10이라 12포트 출력 카드(HOS12·COS12)를 꽂을 수 있는지는 확인이 필요합니다. 기존 `SPX_CARD_ALLOWLIST` 확인 필요 안내가 그대로 표시됩니다.

## 변경

- `src/core.js`
  - `slotPlans`에 XDM과 SPX를 함께 둡니다. `slotPlan(family, model)`을 노출합니다.
  - 불러오기: 슬롯 표가 있는 모델은 예전 논리 슬롯(in-a·in-b·out-a·out-b)을 실제 슬롯 1·2로 옮깁니다. 옮길 슬롯이 없는 경우(M810의 in-b·out-b)는 카드와 전송기 연결을 제외합니다. 없는 슬롯을 만들 수 없기 때문입니다.
  - 검증: SPX는 `SLOT_LAYOUT`(VALID), SPX-RX 연결 시 `SPX_RX_POC`(VALID) 안내를 추가했습니다.
  - `defaultLinks`에 `SPX-COS12 → SPX-RX`를 추가했습니다.
- `src/app.js`
  - SPX는 가로 카드를 입력 위·출력 아래로 쌓는 랙(`rt-rack-hs`)으로 표시합니다. 슬롯 번호표는 나사를 가리지 않도록 나사 오른쪽에 둡니다.
  - 섀시 카드: 입력·출력 슬롯 수를 따로 표시하고, SPX 최대 채널은 카탈로그 표기(modelNotes)를 씁니다.
  - 구성 요약: 채널 용량을 "슬롯 수 × 해당 방향 카드의 최대 포트 수"로 계산합니다(SPX 입력 8, 출력 12).
  - SPX-RX 타일(사양서 값), SPX 안내 문구를 추가했습니다.
- 자산: `output/design/assets/cards/SPX-*.webp` 5장(카드 4종 + 블랭크)입니다. `scripts/tools/extract_spx_catalog_cards.py`로 SPX 카탈로그 스캔 4쪽에서 만든 **임시** 이미지입니다.

## 남은 일

- 채팅에 첨부된 SPX 사진(M810 전면·후면, M1620 전면, M3236 전면·후면 3장)은 파일로 저장되지 않아 쓰지 못했습니다. 파일로 받으면 다음을 합니다.
  - 전면 사진을 섀시 카드에 적용합니다.
  - M810·M3236은 XDM처럼 후면 사진 위에 슬롯을 겹쳐 보여 줍니다.
  - 후면 사진에서 카드 판넬을 고해상도로 다시 잘라 임시 이미지를 교체합니다.
- M1620·M2472·M24120 후면 사진

## 되돌리는 방법

이 PR의 병합 커밋을 revert하면 SPX는 논리 슬롯(2+2)으로 돌아갑니다. 0.10에서 저장한 SPX 구성(in-1…)은 0.9에서 "지원하지 않는 슬롯"으로 거부되므로, 되돌리기 전에 JSON으로 백업한 뒤 다시 구성해야 합니다.
