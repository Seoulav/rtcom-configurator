# 0.255.0 세션 시작 점검: 여러 세션 작업 충돌 줄이기 (2026-10-18)

## 1. 요청과 원인

- 사용자 요청 2026-10-18: 다음 단계 제안 1번("작업 충돌 줄이기")과 "1~2번 진행해줘".
- 원인: 이 저장소는 세션 여러 개가 동시에 작업합니다. 한 세션이 0.253.0을 먼저 병합하면 다른 세션의 같은 번호 묶음이 충돌했고, `CHANGELOG.md`·`CLAUDE.md`·`README.md`·`index.html`은 병합할 때마다 겹쳤습니다(0.153~0.159, 0.253~0.254에서 반복). 세션이 자기 브랜치가 뒤처졌는지 병합 직전에야 알게 되는 것이 문제였습니다.

## 2. 변경

- `scripts/session-preflight.cjs`(새 파일): 세션이 시작될 때 `git fetch origin main` 한 번 뒤에 아래를 알려 줍니다. 파일을 바꾸지 않고, 네트워크·git 오류가 있어도 아무것도 출력하지 않고 exit 0으로 끝나 세션 시작을 막지 않습니다.
  - 브랜치 이름, 이 브랜치와 main의 화면 버전, main이 이 브랜치보다 앞선 커밋 수와 제목(다른 세션이 먼저 병합한 작업).
  - main과 이 브랜치가 **같은 파일을 모두 바꾼** 충돌 후보. 기록 파일(`CHANGELOG.md`·`CLAUDE.md`·`README.md`·`index.html`)은 따로 분류해 "main 내용을 먼저 두고 이 브랜치 항목을 새 번호로 다시 넣는다"는 해결 방법을 알려 줍니다.
  - 다음 병합 번호(main + 1), 번호가 겹칠 때의 경고, 열린 PR은 GitHub에서 확인하라는 안내.
  - `--list`는 같은 글을 일반 글로 보여 줍니다.
- `.claude/settings.json`: SessionStart 훅 두 번째 항목으로 등록했습니다(첫 번째 input_doc 알림은 그대로).
- `CLAUDE.md` "여러 세션이 동시에 작업할 때"에 "작업을 시작할 때" 규칙(점검 결과 확인 → 열린 PR에서 같은 파일을 쓰는 PR 확인 → 겹치면 먼저 병합되길 기다리거나 사용자에게 알림 → 기록 파일 충돌은 번호 이동으로 해결)을 더하고, 병합 직전 순서에 "열린 PR 확인"과 "검사 성공 알림이 이전 커밋의 것이면 쓰지 않고 최신 커밋 결과 확인"을 적었습니다.

## 3. 경계

- 열린 PR은 GitHub 연결이 필요해 이 스크립트가 보지 못합니다. 안내 문구만 붙이고, 확인은 세션이 GitHub 도구로 합니다.
- 충돌 후보는 "두 쪽이 같은 파일을 바꿨다"는 뜻이지 실제 충돌을 보장하지 않습니다.
- 훅이 없는 환경(웹 세션 등)에서도 `node scripts/session-preflight.cjs --list`를 직접 실행해 같은 점검을 할 수 있습니다.

## 4. 검증

- `tests/session-preflight.test.cjs` 4개: 계산(`analyze`), 문장(`describe`), 훅 등록(첫 훅 유지), 임시 git 저장소(원격 + 작업본 + 다른 세션 작업본)에서 main이 앞서고 같은 파일을 바꿨을 때의 JSON과 `--list`, main 병합 뒤 알림 사라짐, `origin/main`이 없거나 저장소가 아닐 때 조용히 종료.

## 5. 되돌리기

`.claude/settings.json`에서 두 번째 SessionStart 항목을 지우면 훅이 꺼집니다. 스크립트와 `CLAUDE.md` 규칙은 지워도 다른 기능에 영향이 없습니다.
