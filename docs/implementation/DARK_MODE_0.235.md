# 다크 모드 0.235 (B단계 ②: 다크 값 연결)

## 무엇을 했나
- 기기 설정이 다크일 때(`@media screen and (prefers-color-scheme:dark)`) 사이트가 검정 페이지·어두운 카드로 바뀝니다. 라이트 화면과 인쇄는 바뀌지 않습니다.
- 다크 값은 `scripts/tools/dark_tokens.cjs`가 계산해 `src/styles.css` 맨 끝의 "0.235 다크 값" 블록에 씁니다. 손으로 고치지 않고 도구를 다시 실행합니다.
- 기준값(2026-10-16 승인 계획): 페이지 `#000`, 카드 `#1C1C1E`, 안쪽 면 `#2C2C2E`, 글자 `#F5F5F7`, 보조 글자 `#8E8E93`, 선 `rgba(84,84,88,.42)`, 강조 글자 `#409CFF`, 강조 면 `#0A84FF`, 유리 면 `rgba(44,44,46,.58)`. 배경 그라데이션도 어두운 판으로 바꿨습니다.

## 계산 규칙(도구)
| 대상 | 규칙 |
|---|---|
| 0.232 변수 `--rt-bg-*` (면) | 흰색 → `#1C1C1E`, 옅은 회색 → `#2C2C2E`, 중간 회색 → `#3A3A3C`, 옅은 색조 면(안내 상자) → 같은 색상의 짙은 면. 이미 어두운 면·채도 높은 면은 그대로 |
| `--rt-fg-*` (글자) | 짙은 회색 → `#F5F5F7`·`#D1D1D6`·`#98989D`, 강조·상태 색 → 같은 색상의 밝은 값(`#0057D8`·`#007AFF`는 `#409CFF`). 이미 밝은 글자(랙 그림·코드 상자 위)는 그대로 |
| `--rt-ln-*` (선) | 옅은 회색 → `#38383A`·`#48484A`, 옅은 색조 → 짙은 색조. 선택·포커스처럼 색이 뚜렷한 선은 그대로 |
| 변수로 모으지 못한 직접 적힌 색(유리 배경 `rgba(255,255,255,.72)` 등) | 같은 선택자로 다크 값 덮어쓰기(41곳, 자동). 인쇄·보고서 규칙과 `#rtcom-design` 밖 규칙은 제외 |
| 기본 변수 `--rt-bg`·`--rt-ink`·`--pg-*` | 위 기준값 |

## 밝게 유지하는 것
- **사진 판넬**: `--rt-photo`(제품 사진 받침)는 다크 값을 두지 않습니다. 카드 판넬 사진 받침(카드 정보 타일·카드 상세 팝업)은 0.178 결정대로 옅은 회색입니다.
- **그림 판**: 자바스크립트가 SVG에 색을 직접 적은 그림(제품 상세 그림 `.rt-pg-svg-wrap`, 화면 구성 미리보기, 딥 스위치·로터리, WOS100 레이어 팝업, 크게 보기 창)은 같은 짙은 글자색이 흰 장비 상자 안과 바깥에 함께 쓰여 일괄로 바꿀 수 없습니다. 다크에서도 흰 판을 깔고 판 안의 색 변수를 라이트 값으로 되돌립니다. 그림별 다크 색은 B③에서 정합니다.
- **구성 보고서 미리보기**(06 내보내기 `.rt-report-paper`): 인쇄물과 같아야 하므로 라이트입니다.
- **인쇄**: 블록이 `screen` 조건 안에만 있어 기기가 다크여도 인쇄는 라이트입니다(브라우저 확인: print+dark에서 `--rt-bg-fff`=`#fff`, `--pg-ink`=`#1C1C1E`).
- 신호 배지에는 다크에서만 옅은 테두리(`rgba(255,255,255,.28)`)를 둡니다(SDI 검정·HDMI 남색이 묻히지 않게).

## 검증
- `node scripts/tools/dark_tokens.cjs --check`: 블록이 최신(단위 테스트 `tests/dark-mode.test.cjs` 5개에 포함).
- 라이트 화면: 변경 전후 11개 화면(1440px) 픽셀 비교, 자동 저장 시각 글자와 XDM-PSU 애니메이션 말고는 같음.
- 다크 화면: 구성기 01~06·카드 선택 팝업·HOS100 팝업, 제품 목록과 33종 상세·WOS100 팝업·문서 팝업·크게 보기 창(1440px·390px)을 찍어 확인하고, 브라우저에서 밝은 면·낮은 대비 글자(HTML)와 SVG 글자 대비를 자동 검사해 라이트 기준과 같은 목록(원래 있던 FIBER 배지 등)만 남는 것을 확인했습니다.
- 단위 테스트 136, 제품 색인·패키징, e2e 통과.
