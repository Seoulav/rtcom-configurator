# AMX LAN(TCP) 제어 알티컴 회신 반영 (0.241)

사용자 전달 2026-10-16(알티컴 회신, 질문 목록의 번호에 맞춰 답함): "17. 23 포트 / 18. RS232 와 동일하게 전송 / 19. 동시접속 수 1, 자동으로 끊기지 않음". 질문은 `docs/handoff/RTCOM_QUESTIONS_2026-10-16.md`입니다.

## 1. 반영한 것

| 질문 | 회신 | 반영 |
|---|---|---|
| 17 TCP 포트 | 23 | XDM·VDM·SPX·QMS-44UX·QMS-88UX·HDS-42MU·HDS-21U의 `controlExample.lan.port`를 23으로(7개 제품 모두 같은 값으로 적용), AMX LAN 코드의 포트 기본값 |
| 18 전송 형식 | RS-232와 동일 | 화면의 "RS-232와 같다고 보고 만든 예시" 문구를 "RS-232와 같습니다"로 확정 |
| 19 연결 방식 | 동시 접속 1개, 자동으로 끊기지 않음 | `lan.connections: 1`, `lan.autoDisconnect: false`. AMX LAN 코드에 "동시 접속 1개" 주석과 OFFLINE 주석("자동으로 끊지 않음, 케이블·전원·다른 접속이 원인") |

- `lan.confirmed: true`인 제품만 확정 문구를 보여 주고, `lan`이 없는 제품은 이전처럼 포트 0·"알티컴 확인 필요" 주석으로 나옵니다.
- 출처 표기는 "알티컴 회신(사용자 전달 2026-10-16)"입니다. SPX는 매뉴얼 46쪽 Telnet 포트 23과 같다는 점을 덧붙였습니다.

## 2. 가정과 한계

- 질문 17번은 제품별 포트를 물었는데 답이 "23 포트" 하나여서 7개 제품 모두에 같은 값을 넣었습니다. 제품별로 다르면 해당 제품 JSON의 `controlExample.lan.port`만 고치면 됩니다.
- 끝 문자(CR/CRLF)와 응답 형식은 "RS-232와 동일"로 처리했고 따로 확인하지 않았습니다. 코드는 RS-232와 같이 `$0D`를 붙입니다.
- 20번(제품별 공장 기본 IP·서브넷·게이트웨이·DHCP)은 회신이 없어 질문 목록에 남겼습니다. 화면 IP 안내는 기본 대역 192.168.1.xxx 그대로입니다.
- 동시 접속이 1개라서 AMX가 접속한 동안에는 PC 웹 화면이나 다른 컨트롤러가 접속하지 못할 수 있습니다. 이 점을 코드 주석에만 적었고 별도 경고 화면은 만들지 않았습니다.

## 3. 검증

- 단위 테스트: 7개 제품의 `lan` 값, LAN 코드의 포트·주석·이벤트 구조, `lan` 없는 제품의 "확인 필요" 표기, 잘못된 포트가 제품 기본값(23)으로 돌아가는지.
- e2e: XDM·SPX 화면에서 LAN 기본 코드에 포트 23·"동시 접속 1개"가 나오고 IP·포트 입력이 그 자리에서 반영되는지.

## 4. 되돌리기

7개 제품 JSON의 `controlExample.lan`을 이전 값(SPX만 `port:23`, 나머지는 삭제)으로 되돌리고 `src/control-example.js`의 `amxCode` 주석 두 곳(`connections`·`autoDisconnect`)과 `commBarHtml`의 `confirmed` 문구를 지우면 0.240 상태입니다.
