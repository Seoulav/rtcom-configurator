# 0.171.0 03 카드 슬롯 ② 신호 입력

사용자 요청·결정 2026-09-29:
- 사용자 제공 표(입력슬롯·슬롯내·신호명 / 신호명·출력슬롯·슬롯내)를 "어디에 넣으면 좋을까?"
- "슬롯을 구성하고 나서 실제 신호를 넣는 거는 어떄?", "그러면 카드 구성이 모두 되니까"
- 선택지 A(03 안에서 신호 입력 화면으로 전환)·B(새 04 단계) 중 "추천A대로 진행해줘"

## 1. 흐름

| 화면 | 다음 버튼 | 이전 버튼 |
|---|---|---|
| 03 ① 카드 장착(카드 없음) | 04 전송기(전과 같음) | 02 프레임 |
| 03 ① 카드 장착(카드 있음) | 03 ② 신호 입력 | 02 프레임 |
| 03 ② 신호 입력 | 04 전송기 | 03 ① 카드 장착 |

- 카드가 한 장이라도 있으면 03 제목 아래 "① 카드 장착 / ② 신호 입력" 탭이 나오고, 언제든 오갈 수 있습니다.
- 지금 어느 화면인지(`signalView`)는 화면 전용 상태라 구성 파일에 저장하지 않습니다. 다른 단계로 가면 ① 카드 장착으로 돌아옵니다.
- 단계 번호(01~06)는 바꾸지 않았습니다(선택지 B를 고르지 않은 이유: 저장된 `step` 값이 밀려 예전 구성 파일이 다른 화면으로 열림).

## 2. 신호 입력 표

- INPUT / OUTPUT 두 표를 나란히 두고(좁은 화면에서는 위아래), 카드마다 포트 수만큼 줄을 만듭니다.
- 슬롯 칸: 채널 범위 배지(`IN 1~4`, 슬롯 번호 × 카드당 최대 포트 기준), 슬롯 이름(`HDMI #1` = 신호 약어 + 슬롯 번호), 슬롯·모델(`IN 1 · XDM-HIS100`). 왼쪽 띠 색은 신호 색(0.170 회사 범례)입니다.
- 신호명 칸: 최대 40자, Enter 다음 칸(Shift+Enter 이전 칸). 입력 중에는 화면을 다시 그리지 않아 커서가 유지되고, 칸을 벗어날 때 실행 취소 기록을 남깁니다.
- 위쪽 "신호명 입력 N / M 포트"와 아래 다음 버튼("이름 없는 포트 N개 · 그래도 다음" / "신호 입력 완료 · 전송기 연결")이 입력할 때마다 바뀝니다.

## 3. 저장

- 신호명은 `state.portAssignments["슬롯:포트"].assignedDevice`에 넣습니다. 이 칸은 JSON schema 3에 원래 있었지만 화면에서 쓰지 않던 칸이며, 불러올 때 120자까지 검사합니다(`src/core.js`).
- 저장 형식·`rtcom.configuration.v1`·`catalogVersion`·슬롯 ID는 그대로입니다. 예전 구성 파일은 신호명이 빈 채로 열립니다.
- 카드를 끌어 옮기면 `RtCore.moveCard`가 포트 기록을 함께 옮겨 신호명이 따라가고, 카드를 빼면 그 카드의 신호명도 사라집니다.

## 4. 확인할 점(시안)

- 채널 범위(`IN 1~4`)는 "슬롯 번호 × 카드당 4포트" 계산입니다. XDM·VDM(카드당 4포트)은 매트릭스 채널 번호와 같다고 보았고, SPX(입력 8·출력 10~12포트)는 실제 채널 번호 규칙을 확인해야 합니다.
- 05 구성 검토 배정표, 06 출력 인쇄·CSV는 다음 묶음입니다.
