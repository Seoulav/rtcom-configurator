# 02 프레임 선택 미리보기 그림 크기 (0.132.0)

## 요청 (2026-09-29)

- "VDM-8X는 다소 크다 이거보다는 작게해주고 나머지 VDM프레임 크기는 다소 작아서 너가 적정한 크기 판단해서 이미지 개선해줘"
- "이거 다 끝나면 SPX, XDM도 비슷한 컨셉으로 수정해줘"

## 원인

- `src/styles.css`의 미리보기 그림은 높이 **상한**만 있었습니다(위아래 겹침 210px, 한 장 300px, 좌우 나란히 400px). 상한이라 그림이 원래 가로가 넓으면 패널 폭(약 588px)에서 먼저 멈춥니다.
- 그래서 가장 작은 VDM-8X(3U, 483×132mm)·SPX-M810(2U)·XDM-12(4U)는 가로 588px를 채우며 가장 크게 보이고, 큰 프레임은 높이 상한에 걸려 가늘고 작게(VDM-180X 89×300px) 보였습니다. 실제 크기와 보이는 크기의 순서가 반대였습니다.

## 구현

- `src/app.js`
  - `frameRackU`: 프레임별 랙 높이(U). 값은 제품 데이터 `lineup[].rackUnits`와 같습니다(VDM 3·7·12·19·24·27·37·38·39·38, XDM 4·9·9·16·29·40, SPX 2·4·7·8·8).
  - `frameShowHeight(model)`: `round(90 + 410 · ln(U/2) / ln(20))`. 2U → 90px, 3U → 146, 7U → 261, 12U → 335, 19U → 398, 27U → 446, 38U → 493, 40U → 500. 실제 높이 비율(3U:38U = 1:12.7)을 그대로 쓰면 작은 프레임이 보이지 않아 로그로 눌렀습니다.
  - `chassisViewV2()`: 미리보기에 `rt-cg-scaled` 클래스와 `--rt-fh`(px 수)를 붙입니다. 표에 없는 모델은 붙이지 않아 예전 상한이 그대로 적용됩니다.
- `src/styles.css`(파일 끝)
  - `.rt-cg-scaled img{height:calc(var(--rt-fh)*1px);width:auto;max-width:100%;object-fit:contain}`: 상한이 아니라 **정해진 높이**로 그립니다. 폭이 부족하면 `max-width`와 `object-fit:contain`으로 비율을 지키며 줄어듭니다.
  - 정면·후면을 위아래로 겹쳐 보이는 작은 프레임(`.rt-cg-duo-stack`)은 0.9배(둘을 합친 높이가 너무 커지지 않게).
  - 휴대폰(820px 이하)은 0.45배, 최소 56px(SPX-M810 2U가 41px까지 줄어드는 것을 막음).
- 그림 파일은 바꾸지 않았습니다(표시 크기만).
