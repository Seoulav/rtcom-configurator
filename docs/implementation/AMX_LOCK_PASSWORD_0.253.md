# 0.253.0 AMX 코드 잠금 비밀번호 변경 (2026-10-18)

## 1. 요청

- 사용자 요청 2026-10-18: "08 AMX 통합 제어 커맨드 예시 비밀번호는 기존거 삭제하고 새 비밀번호로 변경해줘". 새 비밀번호는 사용자가 채팅으로 알려 주었고, 원문은 이 저장소 어디에도 적지 않습니다.

## 2. 변경

- `scripts/tools/set-amx-password.cjs`로 `src/control-example.js`의 `AMX_LOCK` 한 줄(PBKDF2-SHA256 20만 회, salt·hash)을 새 비밀번호의 변환값으로 바꿨습니다. 기존 변환값(salt·hash)은 덮어써서 남아 있지 않으므로 기존 비밀번호는 더 이상 열리지 않습니다.
- 브라우저에서 이미 잠금을 푼 상태(`sessionStorage`의 `rtcom.amxUnlock.v1`)는 변환값 앞 16자와 비교하므로, 새 변환값이 배포되면 모든 열린 화면이 자동으로 다시 잠깁니다. 별도 삭제 작업이 필요 없습니다.
- 잠기는 범위(AMX NetLinx 코드)와 그냥 보이는 범위(커맨드 문자열·HEX·시뮬레이터 커맨드)는 그대로입니다. 바꾸는 방법은 `node scripts/tools/set-amx-password.cjs "<비밀번호>"`이고 확인은 `--check "<비밀번호>"`입니다(0.239).

## 3. 경계

- 이 잠금은 브라우저에서 비밀번호를 비교하는 "잠금 스티커"입니다(사용자 결정 2026-10-16). 사이트 코드가 공개되어 있어 개발자 도구를 아는 사람은 우회할 수 있고, 변환값이 공개 저장소에 있어 추측하기 쉬운 비밀번호는 시간을 들이면 알아낼 수 있습니다. 진짜 보안이 필요하면 서버 잠금(Cloudflare Worker)을 따로 정해야 합니다.
- 비밀번호 원문은 저장소·CHANGELOG·시험·커밋 메시지에 넣지 않았습니다.

## 4. 검증

- `set-amx-password.cjs --check`로 새 비밀번호는 "일치", 다른 값은 "일치하지 않습니다"를 확인했습니다. 단위 테스트의 `AMX_LOCK` 형식 시험(원문 없이 변환값)과 화면 시험의 잠금·해제 흐름(시험용 비밀번호로 dist만 바꿔 실행)은 그대로 통과합니다.

## 5. 되돌리기

이전 비밀번호를 알고 있다면 같은 도구로 다시 설정합니다. 기존 변환값은 이 변경으로 사라졌으므로 git 기록(이전 커밋의 `AMX_LOCK` 줄)으로 되돌릴 수도 있습니다.
