# 0.210 알티컴 확인 답 반영(XDM 5건) · 매뉴얼 PDF 공개 결정

## 요청

0.209 다음 단계로 정리한 알티컴 질문(`docs/RTCOM_MANUFACTURER_DATA_REQUEST.md` §5) 중 XDM 1~5번의 답을 사용자가 전달했습니다(2026-10-13). 이 문서는 알티컴 확인 내용을 출처 `U5`("알티컴 확인(사용자 전달)")로 기록합니다.

| 번호 | 질문 | 답(사용자 전달 원문) |
|---|---|---|
| 1 | XDM-WOS100 레이어 3개일 때 쓸 수 없는 포트 | "레이어 1개를 하더라도 WOS카드 전체가 같은 화면 출력이 됩니다." |
| 2 | 회신 메일 EDID 번호가 표준인지 | "발주시에 커스텀 EDID보내주면 저장되서 출고됩니다." |
| 3 | XDM-COS100이 XDM-PHX 전원을 포트마다 받는지 | "COS출력마다 XDM-PHX전원연결해야합니다." |
| 4 | XDM-WOS100 오디오 단자 | "WOS100 카드는 오디오 출력은 없어" |
| 5 | XDM-288 판매 여부 | "주문생산방식이야" |

같은 대화에서 사용자가 "모든 매뉴얼 PDF 공개합니다"라고 결정했습니다. 대상은 0.209 보고에서 제시한 4건입니다(§6).

## 1. XDM-WOS100: 레이어를 쓰면 카드 4포트가 같은 화면

**0.209와 달라진 점:** 0.209는 사용자 확인("불가 (HOS100과 같음)")에 따라 HOS100 규칙을 WOS100에도 그대로 적용했습니다. 레이어 2개면 1·2번, 3·4번이 짝이고, 4개면 2~4번을 쓸 수 없다는 규칙입니다. 알티컴 답에 따르면 WOS100은 레이어 수와 상관없이 레이어를 쓰면 카드 4포트가 모두 같은 화면을 냅니다. 그래서 짝 포트 규칙을 WOS100에서 뺐습니다. HOS100 규칙은 그대로입니다.

| 위치 | 0.209 | 0.210 |
|---|---|---|
| 레이어 팝업 포트 칩(`wosLayoutCards`) | 레이어 4개 5종은 1번 합성·2~4번 1번 동일, 레이어 2개 1종은 1번 합성·2번 불가·3·4번 사용 | 6종 모두 1번 합성·2~4번 1번 동일 |
| 안내 상자(`.rt-wos-warn`) | "레이어는 카드 출력 포트 자원을 함께 씁니다(HOS100과 같음)", 레이어 3개는 미확인 | "레이어를 쓰면 카드 4포트가 모두 같은 화면을 냅니다", 레이어 1개라도 같음, HOS100과 다름, 포트를 각각 쓰려면 스위칭 모드 |
| 비교표 WOS100 행 | 레이어 4개면 2~4번 포트 사용 불가 | 레이어를 쓰면 카드 4포트가 같은 화면 |
| 카드 설명·출력 카드 선택 TIP | 레이어를 쓰면 일부 포트 사용 불가 / HOS100과 같이 짝 포트 | 레이어를 1개만 써도 4포트 같은 화면, 2~4번 따로 사용 불가 |
| 카드 사양 "레이어 포트 제한" 행 | 레이어 2개 짝 / 4개 사용 불가 | 레이어를 쓰면(1개라도) 4포트 모두 같은 합성 화면, 2~4번 따로 사용 불가 |
| 구성도 OUT 2~4 상자 | 그대로("1번과 같은 화면 · 사용 불가") | 그대로(주석만 정정) |

- **커맨드 설명:** WOS100 팝업의 커맨드 설명("레이어마다 같은 카드의 출력 포트 하나를 자원으로 지정")은 유지했습니다. 커맨드 가이드 44~45쪽 Wall Overlay 커맨드가 겹침 순서를 카드 출력 포트 번호(`P1234`, Slot output priority)로 정하기 때문입니다.
- **스타일 정리:** 0.209에서 WOS100 칩에만 쓰던 `.rt-hos-port-free` 스타일은 쓰는 곳이 없어 지웠습니다.

## 2. XDM-WOS100 오디오 출력 없음

- **카드 사양:** `src/card-specs.js` WOS100에 `['오디오','오디오 출력 없음']` 행을 더했습니다. 답에 없는 "HDMI 임베디드 오디오" 같은 내용은 덧붙이지 않았습니다.
- **공개 JSON:** `xdm.json` WOS100 영상 행 `condition`에 "오디오 출력 없음(알티컴 확인 2026-10-13)"을 적었습니다. 오디오 행은 0.208처럼 두지 않습니다.

## 3. XDM-COS100: 출력마다 XDM-PHX 전원

**BOM 계산(`src/core.js` `ctrPower`):** XDM-PHX 수량을 COS100에 연결한 CTR100 RX 대수(`link.count`)로 셉니다. 0.72~0.209는 CTR100 RX를 연결한 COS100 카드 장수(카드마다 1)로 셌습니다. XDM-PSU 대수는 지금처럼 `(POH + PHX) ÷ 16` 올림이라 함께 늘어날 수 있습니다.

| 예(단위 테스트 구성) | 0.209 | 0.210 |
|---|---|---|
| CIS100에 CTR100 TX 2대, COS100 1장에 CTR100 RX 3대 | POH 2 · PHX 1 · PSU 1 | POH 2 · PHX 3 · PSU 1 |

함께 고친 곳:

- **04 전송기 전원 안내:** "COS100 출력 1포트당 1개"로 바꿨습니다.
- **02 프레임 선택 "함께 보면 좋은 제품":** XDM-PSU 설명을 같은 기준으로 고쳤습니다.
- **XDM-PSU 제품정보(`xdm-psu.json`):** 개요, 05 주요 기능, 04 제품 사양 XDM-PHX 행, PHX 단자 행을 고쳤습니다. 이 항목들의 출처는 `U5`입니다. 검증 요약에도 정정 사실을 적었습니다.
- **XDM-PSU 03 Signal Flow 설명 줄:** "PHX 1개 = COS100 출력 1포트(CTR100 RX 1대)"로 바꿨습니다. 그림은 COS100 1번 포트에 PHX 1개를 꽂는 모습이라 새 규칙과 맞아 그대로 둡니다.
- **공개 JSON `xdm.json` XDM-COS100 Power 행:** `quantity "4"`, `VERIFIED`, 출처 `U5`로 고쳤습니다(0.208은 수량을 비우고 `REVIEW REQUIRED`). U3 출처 설명에도 정정 사실을 적었습니다.

## 4. 커스텀 EDID 출고

- **XDM 05 주요 기능:** "커스텀 EDID 출고 지원(발주 시 EDID 파일을 보내면 저장해 출고)"을 더했습니다(출처 `U5`).
- **넣지 않은 내용:** 알티컴 기술 회신 메일에 나온 EDID 번호는 현장용 커스텀 번호이므로 공개 데이터에 넣지 않습니다(0.209 원칙 유지).

## 5. XDM-288 주문 생산

- **표기:** `xdm.json` 라인업 요약을 "주문 생산 모델(알티컴 확인 2026-10-13) · 채널·크기·무게 사양 미수록"으로 바꿨습니다. 개요 마지막 문장은 "메인프레임은 XDM-12부터 XDM-216까지 6종이며, XDM-288은 주문 생산한다."로 바꿨습니다.
- **슬롯 수:** 보드 수는 아직 없어 `slots`를 넣지 않았습니다. 구성기에서도 0.29 결정대로 계속 제외합니다. 남은 질문은 `docs/handoff/OPEN_ITEMS.md`에 있습니다.
