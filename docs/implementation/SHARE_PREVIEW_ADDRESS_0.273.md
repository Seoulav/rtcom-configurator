# 0.273.0 주소창 주소로도 제품 미리보기 (2026-11-23)

## 1. 요청과 배경

- 사용자 요청 2026-11-23: 카카오톡 캡처와 함께 "카카오톡 제대로 안되", 이어서 0.272 보고의 선택지(A 현재 방식 유지 / B 주소창 주소를 공유 주소로 변경)에 "너가 판단해서해줘".
- 캡처는 주소창의 `…/#products/hd-13u`를 그대로 보낸 것이었고 카드에는 첫 화면의 옛 정보(제목 "RTCOM 매트릭스 구성기", 설명 "여기를 눌러 링크를 확인하세요.")가 나왔습니다. 서버는 정상(카카오톡 수집기 방식으로 읽으면 제품 공유 주소·이미지가 모두 정상)이라 원인은 두 가지였습니다: `#` 뒤는 수집기에 전달되지 않음, 첫 화면 미리보기를 카카오톡이 옛 내용으로 기억함.
- 판단: 사용자는 버튼으로 복사한 주소가 아니라 주소창 주소를 그대로 붙이고(처음 요청도 "모든 제품 링크 보냈을때 가능하게"), A는 이 사용을 풀지 못합니다. B 중에서 `<base>` 태그나 하위 폴더를 쓰는 방식은 모든 상대 경로와 내부 링크를 건드려 위험이 컸고, **같은 폴더의 파일 이름만 바꾸는 방식**이 상대 경로를 그대로 두는 가장 안전한 방법이라 이를 택했습니다.

## 2. 동작

| 상황 | 주소창 |
|---|---|
| 제품 상세(시리즈 상세 포함)를 연다 | `…/rtcom-configurator/product-<id>.html#products/<id>` |
| 제품 목록·구성기 화면으로 간다 | `…/rtcom-configurator/#products` 또는 `#matrix-configurator`(첫 화면 주소) |
| `product-<id>.html`을 `#` 없이 연다 | 제품 상세가 열리고 `#products/<id>`가 붙는다 |
| 옛 별칭 `#products/hd-14u` | 정식 id로 바뀐 뒤 `product-hd-104u.html` |
| 새로고침 | 같은 제품 페이지가 다시 열린다 |
| 뒤로·앞으로 가기 | 각 기록의 주소와 화면으로 돌아간다 |

- `product-<id>.html`은 `index.html` 전체에서 `<title>`·`description`·`og:*`·`twitter:*`만 그 제품 것으로 바꾼 파일이라 카카오톡이 `#` 앞의 주소를 읽어도 제품 이름·설명·사진이 나옵니다(33종, 본문은 `index.html`과 같음을 시험이 비교).
- 호환성 계약(`#matrix-configurator`·`rtcom.configuration.v1`·0.6 포털 주소 이동)은 바뀌지 않았습니다. `#` 뒤 값과 라우팅 규칙은 그대로이고, 제품 화면에서만 파일 이름이 달라집니다.

## 3. 구현 위치

| 파일 | 내용 |
|---|---|
| `scripts/build-share-pages.cjs` | `productPageHtml`(템플릿 head 교체, 해시 보정 한 줄)·`writeSharePages`가 `dist/product-<id>.html`과 옛 `dist/share/<id>/`를 만든다. `index.html` head 형식이 바뀌면 빌드가 멈춘다. |
| `src/products.js` | `syncProductAddress`(주소의 파일 이름만 바꿈, 폴더·`?`·`#`·기록 상태 유지), `show()` 안의 호출 두 곳(비제품 화면은 즉시, 제품은 정보를 불러와 유효한 id일 때), `popstate` 처리, "링크 공유" 주소를 `product-<id>.html`로 |
| `tests/site.test.cjs` | 제품 페이지 33종·주소 맞춤 소스·기존 안전 시험 조정 |
| `scripts/e2e-smoke.cjs` | 주소 맞춤 화면 시험 12개 |

## 4. 시험이 잡은 문제

- 상세에서 뒤로 가기를 눌러도 화면이 이전 제품에 머물렀습니다. 주소의 파일 이름까지 달라지는 이동은 브라우저가 `hashchange` 없이 `popstate`만 보내는데 앱은 `hashchange`만 들었기 때문입니다. `popstate`도 듣게 고쳤고, 두 신호가 겹치면 한 틱 뒤 이미 그린 화면(`lastShownHash`)이면 건너뜁니다.
- 기존 안전 시험("주소 기록은 항상 현재 주소 그대로")이 실패했습니다. 이번 변경은 폴더를 그대로 두고 파일 이름만 바꾸므로 규칙의 의도(상대 경로가 깨지지 않을 것)를 지킵니다. 시험을 이 한 곳만 허용하도록 좁히고, 폴더 유지·호출 한 곳이라는 조건을 따로 시험합니다.

## 5. 한계와 사용자가 할 일

- 이미 보낸 옛 형식 주소(`…/#products/…`)와 직접 만든 `#` 주소는 `#` 앞이 첫 화면이라 첫 화면 카드가 나옵니다. 제품 화면에서 주소창 주소(또는 "링크 공유" 버튼 주소)를 새로 복사해 보내야 합니다.
- 카카오톡은 한 번 읽은 주소의 미리보기를 한동안 기억합니다. 새 제품 주소는 처음 읽는 주소라 바로 나오고, 첫 화면 주소의 옛 카드는 카카오 공유 디버거(https://developers.kakao.com/tool/debugger/sharing)에서 주소를 넣고 "초기화"해야 새로 나옵니다(카카오 계정 필요).
- 이 환경에서는 카카오톡 앱으로 직접 확인할 수 없어 배포 뒤 공개 주소에서 태그와 이미지 응답을 내려받아 확인하고(`docs/qa/DEPLOYMENT_0.273_*.md`), 앱 표시는 사용자가 확인해야 합니다.

## 6. 되돌리기

PR을 revert하면 0.272 상태(`share/<id>/`와 "링크 공유" 버튼만 있는 상태)로 돌아갑니다. 일부만 되돌릴 때: 주소 바꾸기는 `src/products.js`의 `syncProductAddress`와 `show()` 안의 호출 두 곳·`popstate` 줄을, 제품 페이지는 `writeSharePages`의 `product-<id>.html` 쓰기를 지웁니다(안전 시험의 예외도 함께 되돌림).
