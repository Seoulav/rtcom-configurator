# Analog Way 구성기 재확인 (2026-09-27)

- 요청: "모듈러 매트릭스 구성기의 기본 컨셉은 아날로그웨이와 동일해야 한다"(사용자, 2026-09-27)
- 확인 방법: https://www.analogway.com/configurator (Aquilon)를 세션 프록시 CA 번들로 받아 렌더링하고 캡처했습니다. 0.8.0 당시에는 인증서 문제로 원문 텍스트만 봤습니다. 캡처는 경쟁사 저작물이라 저장소에 넣지 않았습니다.
- 결론: RTCOM 구성기는 **구조(화면 배치·흐름)는 Analog Way**, **스킨(글꼴·색·카드)은 LED 구성기(svt-led-calculator)**로 갑니다.

## Analog Way 구성기의 구조

| 항목 | Analog Way | RTCOM 현재(0.31) | 판정 |
|---|---|---|---|
| 단계 | 1 Chassis → 2 VPU → 3 IPU → 4 MVR → 5 I/O → 6 Export | 01 제품군 → 02 섀시 → 03 카드 슬롯 → 04 전송기 → 05 구성 검토 → 06 내보내기 | 같은 방식. VPU·IPU·MVR은 RTCOM에 해당 부품이 없어 제품군·전송기 단계로 대체 |
| 단계 표시 | 오른쪽 위 가로 탭. 완료 단계는 체크, 현재 단계는 파란 밑줄 + 넓은 칸 | 가로 6칸 버튼 | **바꿔야 함**: 밑줄형 탭 + 완료 체크 |
| 선택 단계 화면 | **왼쪽 절반 = 선택 목록**(이름 · 사양 2~3줄 · 오른쪽 위 상태 점), **오른쪽 절반 = 선택한 섀시 그림이 고정된 미리보기**(연하늘 배경) | 사진 카드 격자(한 화면 전체) | **바꿔야 함**: 섀시·전송기 단계를 "왼쪽 목록 + 오른쪽 고정 미리보기"로 |
| 선택 표시 | 목록 행 배경이 연하늘로 바뀌고, 테두리가 파랑, 상태 점이 초록 | 파란 테두리 + 원형 체크 | 목록형으로 바꾸면서 맞춤 |
| 입출력 카드 단계 | 가운데 제목 "빈 칸을 눌러 카드 선택" + **실제 후면 사진 위 빈 칸**(흰색 = 장착 가능, 짙은 회색 = 불가) + 아래 "Confirm selection" | 후면 사진 위 슬롯 + 오른쪽 구성 요약 | 거의 같음. 유지하고 "선택 완료" 버튼만 후면 아래로 |
| 카드 선택 | 팝업 목록: 카드 이름 · 포트 수 · 부품번호(OPT-…) · 카드 그림 | `<dialog>` 팝업: 카드 사진 · 포트 수 | 같음 |
| 스크롤 | 한 페이지에 단계가 차례로 쌓이고 단계 표시가 따라감 | 한 번에 한 단계만 보임 | 현행 유지(RTCOM 저장·실행 취소 구조와 맞음). 바꾸지 않음 |
| 내보내기 | 이름·이메일 등 입력 뒤 PDF 메일 발송 | 입력 없이 JSON·CSV·인쇄 | 현행 유지(0.8.0 결정: 개인정보 입력 제외) |

## 구성기 시안에 반영할 것 (프롬프트 7 전 시안 재작업)

1. 단계 표시를 밑줄형 탭으로 바꿉니다(완료 체크, 현재 단계 파랑). 색·글꼴은 LED 구성기 토큰을 씁니다.
2. 02 섀시와 04 전송기는 왼쪽 목록 + 오른쪽 고정 미리보기(선택한 프레임 전면·후면 사진, 전송기는 카드 후면 + 연결 전송기 사진)로 바꿉니다.
3. 01 제품군도 같은 좌우 구조로 바꿉니다(오른쪽 = 제품군 대표 사진).
4. 03 카드 슬롯은 현행을 유지하고, 안내 제목을 가운데 정렬하고, 후면 아래에 "선택 완료 →" 버튼을 둡니다.
   - **빈 슬롯은 흰색 빈칸**으로 둡니다(사용자 결정 2026-09-27, Analog Way 방식). 지금 쓰는 블랭크 커버 합성 이미지(`XDM-BLANK.webp`)는 쓰지 않습니다. 흰 칸에는 회색 테두리와 슬롯 번호를 두고, 마우스를 올리면 "+"가 보입니다. 선택 중인 칸은 파란 테두리 + 옅은 파랑입니다. 장착한 카드는 실제 판넬 사진입니다.
   - SPX·VDM처럼 사진 슬롯이 아닌 논리 슬롯도 같은 흰 칸 규칙을 씁니다.
5. 05 검토·06 내보내기는 현행 구조에 스킨만 입힙니다.
6. 호환성 계약(슬롯 ID, 저장 키, 스키마, 주소)과 core.js 계산 로직은 바꾸지 않습니다. 화면 함수만 바꿉니다.

## 블랭크 커버 선택 (사용자 결정 2026-09-27)

> "블랭크 슬롯은 슬롯을 전부 꽉 채우지 않았을 때 블랭크 슬롯을 선택할 수 있게 해서 완성할 수 있게 해 줘"

Analog Way도 카드 목록에 `FILLER (no connector)`를 함께 둡니다. RTCOM도 같은 방식을 씁니다.

### 동작
1. 카드를 꽂지 않은 슬롯은 **흰 빈칸**입니다. 이 상태는 "미완성"입니다.
2. 슬롯을 누르면 팝업 **맨 위에 "블랭크 커버(커넥터 없음 · 0포트)"**가 있고, 그 아래 입력·출력 카드 목록이 나옵니다.
3. 팝업 아래 버튼: `슬롯 비우기(흰 칸)`는 카드나 블랭크를 빼서 흰 칸으로 되돌리고, `닫기`는 그냥 닫습니다.
4. 후면 아래에 `비어 있는 슬롯 N개 — … 남은 N칸 블랭크로 채우기` 버튼 줄이 있습니다. 누르면 **흰 칸만** 한꺼번에 블랭크로 바꿉니다. 이미 넣은 카드는 건드리지 않습니다. 이 동작도 실행 취소 1단계로 기록합니다.
5. 오른쪽 요약에 `슬롯 완성도 N / 전체`, 3색 막대(카드 파랑 · 블랭크 회색 · 빈칸 흰색), `미완성`/`완성` 배지를 둡니다. 블랭크는 "마감재" 묶음으로 수량을 셉니다.
6. 모든 슬롯이 카드나 블랭크면 위에 `✓ N개 슬롯을 모두 채웠습니다 · 구성 완성` 배너를 띄우고, 다음 버튼 문구가 `선택 완료 · 전송기 연결 →`이 됩니다. 빈칸이 남아 있으면 `빈칸 N개 남음 · 그래도 다음 →`입니다. **막지는 않습니다.**
7. 05 구성 검토에 `SLOT_INCOMPLETE`(WARNING) 항목을 추가합니다: "빈 슬롯 N개에 카드나 블랭크 커버가 지정되지 않았습니다." 인쇄·CSV 보고서에도 같은 문구가 들어갑니다.
8. BOM에는 `블랭크 커버 (XDM|SPX|VDM) × N`을 넣고 "부품번호·기본 포함 여부 제조사 확인 필요"로 표시합니다(UNVERIFIED). 블랭크가 프레임에 기본 포함인지, 따로 주문하는 품목인지 자료가 없기 때문입니다.
9. 채널 계산(입력·출력 N / 전체 채널)에는 블랭크를 0채널로 넣습니다.

### 데이터 (호환성 계약 검토)
- 저장 형식: 기존 `placements[slotId]`에 카드 id 대신 **예약값 `"BLANK"`**를 넣습니다. schema 3, `rtcom.configuration.v1` 키, `catalogVersion`, 슬롯 ID는 **바꾸지 않습니다.**
- `catalog.js`에는 블랭크를 카드로 추가하지 않습니다. 따라서 구성기 카드 수 3/21/26 계약은 그대로입니다. `core.js`의 검증은 `"BLANK"`를 모든 제품군·모든 방향 슬롯에 허용하는 특수값으로 처리합니다.
- 이전 버전(0.31 이하)에서 `"BLANK"`가 든 파일을 열면 알 수 없는 카드로 거부됩니다(구버전 → 신버전 방향만 호환). 이 점을 CHANGELOG에 적습니다.
- 흰 칸이 기본이 되므로, 지금 빈 슬롯에 자동으로 씌우던 블랭크 커버 그림(`blankPlates`)은 **사용자가 블랭크를 고른 슬롯에만** 씁니다. `XDM-BLANK.webp` 같은 파일은 그대로 둡니다.
- 테스트: `"BLANK"` 저장·복원, 제품군 변경 시 초기화, 한꺼번에 채우기가 흰 칸만 바꾸는지, 완성도 계산, BOM 행, `SLOT_INCOMPLETE` 경고.
