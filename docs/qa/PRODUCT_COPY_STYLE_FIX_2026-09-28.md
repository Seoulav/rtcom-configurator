# 제품 상세 문체 정리 · HDS-21U 딥 스위치 3번 정정 (2026-09-28)

## 배경

사용자가 업로드한 문체 통일 제안서(`RTCOM_제품상세_문체통일_Claude_제안서_2026-09-28.md`)를 검토해 전수 점검표를 보고했고, 사용자는 우선순위 1(HD-D102U)·3(HDS-21U/42MU "Audio Extraction")·4(HD-210U "Nothing")번을 진행하도록 승인했습니다.

3·4번 작업 중 사용자가 HDS-21U·HDS-42MU 공식 사용자 매뉴얼 Ver.1.0 원본(PDF)을 추가로 제공했고, 대조 결과 기존 데이터의 사실 오류를 발견해 함께 바로잡았습니다.

## 1. HD-D102U 주요 기능 전면 재작성(우선순위 1번)

0.56·0.57·0.64 문체 통일 작업에서 유일하게 빠졌던 제품. `features[]` 7개 중 6개가 영문으로 남아 있던 것을 "~ 지원" 명사형으로 정리했습니다(첫 항목 "HDMI 2.0b, HDCP 2.2 지원"은 이미 통일되어 있어 그대로 둠). HDMI/HDCP/EDID, 해상도·대역폭 수치, VESA·QSXGA 표준명, Dolby/LPCM/DTS-HD 등 오디오 포맷 고유명사는 그대로 보존했습니다. `YCBCR`→`YCbCr`, `60HZ`→`60Hz`는 하우스 표기(다른 제품 조건 필드에서 이미 쓰는 대소문자)에 맞춘 표기 정리이며 기술적 의미 변경이 아닙니다.

## 2. HDS-21U·HDS-42MU "Audio Extraction" 정리(우선순위 3번)

두 제품 `features[]`의 "Audio Extraction 기능: RS232로 Audio Volume Up/Down 제어"를 "오디오 추출 기능: RS-232로 음량 조절 지원"으로 바꿨습니다. 다른 제품·같은 파일의 "오디오 추출"·"RS-232" 표기와 통일됩니다.

## 3. HD-210U EDID 코드표 "Nothing" 정리(우선순위 4번)

`edidSwitch.table`의 C·E 코드 설명 "Nothing"을 형제 제품(HD-104U·HD-108U·HD-13U)과 같은 "미사용(Nothing)"으로 통일했습니다.

## 4. HDS-21U 딥 스위치 3번 "분배" 삭제 — 사용자 제공 매뉴얼 원본 대조로 발견한 사실 오류

0.64.0에서 "HDS-21U 딥 스위치는 HDS-42MU와 같다(1 오디오·2 Priority·3 분배)"로 확정했던 내용이, 이번에 사용자가 제공한 `HDS-21U 사용자 매뉴얼 Ver.1.0`(전체) 원본과 어긋남을 확인했습니다.

- **HDS-42MU 매뉴얼**: "화면분배기능 설정(Distributor)" 절이 별도로 있고, "분배기능 사용시 출력포트 1번과 2번으로 같은 영상이 출력됩니다. … 딥스위치 3번을 On/Off"라고 명시. HDS-42MU는 출력이 2개(OUT1·OUT2)라 분배가 성립합니다.
- **HDS-21U 매뉴얼**: "사용 방법" 절에 케이블 연결 → 오디오 병합·추출(1번 스위치) → 오토스위칭/Priority(2번 스위치) → EDID 선택 순으로만 나오고, **3번 스위치나 "분배"에 대한 절 자체가 없습니다.** 일반사양 표에도 "출력신호: HDMI Single Link **1 port**"로 명시되어 있어, 출력이 1개인 이 제품에는 "출력 1·2번에 같은 영상" 기능이 성립할 수 없습니다.
- 제품 정면 사진(`hds-21u-front.webp`)에는 MODE 라벨 아래 빨간 딥 스위치 토글이 3개 보여, 물리적으로는 3번 스위치 자리가 있지만(HDS-42MU와 같은 PCB를 공유하는 것으로 추정) 매뉴얼에 3번 기능 설명이 없습니다.

**반영**: `data/products/hds-21u.json`의 `dipSwitch.rows`에서 3번("분배") 행을 삭제하고, `dipSwitch.note`에 "3번 스위치는 기능이 없다(사용자 매뉴얼 Ver.1.0에 안내 없음, HDS-21U는 HDMI 출력이 1개라 HDS-42MU의 분배 기능이 적용되지 않는다)"를 추가했습니다(HD-210U 0.66.0의 "3번 기능 없음" 안내와 같은 방식). `dipSwitch.count`는 3을 유지해 그림에는 물리 스위치 3개가 그대로 나옵니다. `portMap`의 MODE 단자 설명도 같은 내용으로 정정했습니다.
