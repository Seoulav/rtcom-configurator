# 입출력 단자 표 "찌그러짐" 전수 조사·수정 QA (2026-09-28)

## 증상

사용자 보고: "제조사 정보를 항상 열면은 표가 약간 찌그러지는 게 있는데 어떤 거는 정상이고 어떤 거는 찌그러지거든." (공개 사이트 HDS-21U 화면 캡처 첨부)

- "제조사 자료" 안 "입출력 단자" 표(`recordSection`, `src/products.js`)의 6개 칸(분류·방향·단자·수량·신호·조건) 중 **방향**("입력"·"출력"·"입출력")과 **수량**(숫자)처럼 원래 한 글자도 줄바꿈될 일이 없는 짧고 고정된 값이, 신호·조건 칸의 긴 문장에 폭을 밀려 좁은 화면에서 한 글자씩 두 줄로 쪼개졌다(예: "입력" → "입"/"력").

## 원인

- `.rt-pg-tablewrap td:first-child`에만 `white-space:nowrap`이 있었고, 나머지 칸(방향·수량 포함)은 지정이 없어 표 폭이 좁아지면 브라우저가 아무 칸이나 줄바꿈해서 채웠다.
- 첫 칸(분류)에는 `width:34%`가 고정돼 있어, 값이 짧은 제품(예: HDS-21U의 "Video"·"Audio")에서도 늘 표 폭의 1/3을 차지해 나머지 5칸이 쓸 수 있는 폭이 좁아졌다. 조건·신호 칸이 길면 이 좁은 나머지 폭 안에서 방향·수량 칸까지 밀려 쪼개졌다.
- 카탈로그 값(조건·신호 문장 길이)이 제품마다 달라 "어떤 건 정상, 어떤 건 찌그러짐"으로 보였다.

## 전수 조사 방법

Playwright로 30개 제품 전체를 6개 화면 폭(320·375·480·600·834·1024px)에서 열어, 입출력 단자 표의 각 칸에 대해 `Range.getClientRects().length`(줄 수)를 직접 재서 실제로 줄바꿈됐는지 확인했다(글자 너비를 따로 추정하는 방식은 `getComputedStyle().font`가 빈 문자열을 돌려주는 경우가 있어 오탐이 나 이 방식으로 바꿨다).

- 수정 전: 방향·수량·분류 헤더/값이 18개 화면 폭 구간 중 여러 곳에서 두 줄로 쪼개짐(HDS-21U를 포함해 QMS-44UX·HD-108U·HD-210U·CT103-U-H/CR103-U·SPX-TX/RX 등 다수).
- 수정 후: 방향("입력"·"출력"·"입출력")·수량(숫자)·분류·단자 헤더가 320~1024px 6개 폭·30개 제품 전체에서 0건.
- 남아 있는 줄바꿈은 모두 단자·신호·조건 칸의 긴 설명 문장(예: "DVI / HDMI (TMDS) · HDMI 1.4b", "5핀 중 접지·Tx·Rx · RS-232C 통신(RS-232+ 제어)")으로, 여러 단어가 있어 자연스럽게 줄바꿈되는 정상 동작이다.

## 수정 내용

- `src/products.js`: 입출력 단자 표에만 `rt-pg-io-table` 클래스를 더해 다른 표(제품 사양 2단, EDID 코드표)에 영향이 없게 했다.
- `src/styles.css`
  - `.rt-pg-tablewrap th:first-child`에도 `td:first-child`와 같은 규칙(고정폭 34%·줄바꿈 없음)을 적용했다(기존에는 `td`에만 있어 헤더 "분류"는 지정이 없었다).
  - `.rt-pg-io-table`에서만 첫 칸(분류)의 `width:34%` 고정을 없애고 내용만큼만 차지하게 해, 남는 폭을 나머지 5칸이 나눠 쓰게 했다.
  - `.rt-pg-io-table`의 방향(2번째)·수량(4번째) 칸에 `white-space:nowrap`을 추가했다.
